# BUG-2026-0088: Text-block emission loses trailing spaces/tabs before line terminators (incidental-whitespace stripping)

**Type**: Bug
**Status**: RELEASED (v1.10.0)
**Severity**: HIGH
**Created**: 2026-06-10
**Resolved**: 2026-06-10
**Cluster**: `textblock-trailing-ws` (construct-matrix gap analysis, fix order #8)
**Parent/related**: NEW — umbrella BUG-2026-0080

## Description

Class of defect: SILENT MISCOMPILATION (recompiles cleanly, computes wrong values). Matrix classes affected: C_TextBlocks.

- **[HIGH] C_TextBlocks**: Silent loss of trailing whitespace in a text-block string constant. The original method escapes() uses '\s\s' to keep two trailing spaces, so the compiled string constant contains "trailing:  \n" (two spaces before the newline). The decompiler re-emits the constant verbatim inside a text block with literal trailing spaces on that line. Per JLS 3.10.6 javac strips trailing whitespace on each text-block line as incidental whitespace, so the recompiled constant becomes "trailing:\n" — a different string value. Verified by runtime round-trip: original class returns 'tab:\tend\nquote:"q"\ntrailing:  \nexplicit-newline:\nmid\n', recompiled-from-decompiled returns 'tab:\tend\nquote:"q"\ntrailing:\nexplicit-newline:\nmid\n'. Root cause: JavaSourceWriter.isTextBlockSafe() (line ~3445) does not reject or \s-escape space/tab characters immediately preceding a line terminator before the verbatim text-block emission at line ~2529 (printer.printStringConstant("\"\"\"\n" + sVal + "\"\"\"")). Same defect would also drop a trailing tab before a newline. Compiles cleanly, wrong value at runtime.
  - original: `return """
        tab:\tend
        quote:\"q\"
        trailing:\s\s
        explicit-newline:\nmid
        """;  // constant contains "trailing:  \n" (2 trailing spaces)`
  - decompiled: `return """
tab:	end
quote:"q"
trailing:  
explicit-newline:
mid
""";  // literal trailing spaces — javac strips them, constant becomes "trailing:\n"`

## Technical Analysis

Root cause documented in the verified semantic-divergence audit (see report-construct-matrix-gap-analysis.md). The mechanism lives in the modules listed below.

### Suggested Approach

JavaSourceWriter.isTextBlockSafe (:3445) does not reject space/tab immediately preceding '\n' before the verbatim emission at :2527-2529. Fix: either reject such constants (fall back to a regular escaped string literal) or \s-escape the last whitespace character of each line ('  \n' -> ' \s\n') so javac preserves the value per JLS 3.10.6. Add a round-trip runtime-value test with 'trailing:  \n'.

## Solution Implemented

Before emitting a string constant verbatim inside a text block, each trailing space/tab run at the
end of every content line (including the final line, whose trailing whitespace before the inline
closing `"""` delimiter is also stripped by javac per JLS 3.10.6) is rewritten escape-by-escape:
each trailing space becomes `\s` and each trailing tab becomes `\t`. Escape sequences are processed
after incidental-whitespace stripping, so the recompiled constant is byte-identical. Interior
whitespace is left verbatim. New helper `escapeTextBlockTrailingWhitespace(String)` added next to
`isTextBlockSafe` and applied at the single text-block emission site in `writeExpression`.
