# BUG-2026-0090: @Retention/@Target and AnnotationDefault dropped on nested annotation types

**Type**: Bug
**Status**: RELEASED (v1.10.0)
**Severity**: HIGH
**Created**: 2026-06-10
**Resolved**: 2026-06-10
**Cluster**: `annotation-metadata` (construct-matrix gap analysis, fix order #10)
**Parent/related**: NEW — umbrella BUG-2026-0080

## Description

Class of defect: SILENT MISCOMPILATION (recompiles cleanly, computes wrong values). Matrix classes affected: C_AnnotationDecl, C_AnnotationUse.

- **[HIGH] C_AnnotationDecl**: @Retention(RetentionPolicy.RUNTIME) dropped from all three nested annotation types (Marker, Name, Config). The bytecode for each annotation class carries RuntimeVisibleAnnotations with Retention=RUNTIME (verified via javap -v on C_AnnotationDecl$Config.class etc.), but the decompiled output has no @Retention at all. Recompiled annotations default to CLASS retention, so all reflection-based consumers (e.g. getAnnotation on C_AnnotationUse members) silently see no annotations at runtime.
  - original: `@Retention(RetentionPolicy.RUNTIME)
@Target({ ElementType.TYPE, ElementType.METHOD, ElementType.PARAMETER })
public @interface Config { ... }`
  - decompiled: `public static @interface Config {
    public abstract String author();
    ...`
- **[HIGH] C_AnnotationDecl**: All AnnotationDefault values on Config dropped: author() default "unknown", version() default 1, tags() default {}, targetKind() default ElementType.METHOD. The class file contains AnnotationDefault attributes for all four elements (verified via javap -v), but the decompiled elements have no defaults. After recompilation every element becomes mandatory: existing uses such as @C_AnnotationDecl.Config(author = "denzo") in C_AnnotationUse fail to compile, and reflective reads of unspecified elements throw IncompleteAnnotationException.
  - original: `String author() default "unknown";
int version() default 1;
String[] tags() default {};
ElementType targetKind() default ElementType.METHOD;`
  - decompiled: `public abstract String author();
public abstract int version();
public abstract String[] tags();
public abstract ElementType targetKind();`
- **[MEDIUM] C_AnnotationDecl**: @Target meta-annotations dropped from all three nested annotation types (Marker: TYPE; Name: METHOD/FIELD/PARAMETER; Config: TYPE/METHOD/PARAMETER) despite being present in the bytecode's RuntimeVisibleAnnotations. Recompiled annotations become applicable to all declaration contexts, so source that the original annotation set would reject (e.g. @Marker on a method, @Name on a class) now compiles — a silent weakening of compile-time checks and a runtime-visible meta-annotation difference for tools reading Target reflectively.
  - original: `@Target(ElementType.TYPE)
public @interface Marker {
}`
  - decompiled: `public static @interface Marker {
}`

## Technical Analysis

Root cause documented in the verified semantic-divergence audit (see report-construct-matrix-gap-analysis.md). The mechanism lives in the modules listed below.

### Suggested Approach

Two gaps: (1) JavaSourceWriter.writeInnerClass (:651-769) never emits inner.getClassAnnotations() — mirror the top-level emission at :343-348 before the keyword block (~:700); the converter already extracts them (extractAnnotations :754). (2) AnnotationDefaultAttribute is parsed (model/classfile/attribute/AttributeParser.java:110-111) but never surfaced: plumb the default ElementValue onto JavaSyntaxResult.MethodDeclaration in ClassFileToJavaSyntaxConverter (method-attribute loop ~:410-450) and emit 'default <value>' in the writer's annotation-element path, reusing the existing writeAnnotation element-value rendering (:3462+). Restores RUNTIME retention, targets, and defaults whose loss currently breaks reflection and makes @Config(author=...) uses uncompilable.

## Solution Implemented

Three coordinated changes (change tags `BUG-2026-0090-20260610-1..9`):

1. **Inner-class annotation emission**: `JavaSourceWriter.writeInnerClass` now emits
   `inner.getClassAnnotations()` before the access-flag/keyword block, mirroring the
   top-level emission in `writeClassDeclaration`. Restores `@Retention`/`@Target` (and any
   other RuntimeVisibleAnnotations) on nested types, including nested annotation types.
2. **AnnotationDefault plumbing**: `ClassFileToJavaSyntaxConverter.convertMethod` reads the
   already-parsed `AnnotationDefaultAttribute` from the method attributes and stores its
   `ElementValue` in the new field `JavaSyntaxResult.MethodDeclaration.annotationDefault`.
   `JavaSourceWriter.writeMethod` renders it as ` default <value>` before the `;` of
   abstract methods when the owner is an annotation type, reusing `writeElementValue`.
3. **Annotation import collection**: `collectImports` previously never collected imports
   for annotation types or their element values, so the newly emitted
   `@Retention(RetentionPolicy.RUNTIME)` would not have resolved. Added
   `collectAnnotationImports`/`collectAnnotationImport`/`collectElementValueImports`/
   `addDescriptorImport` helpers and wired them for class-level, field, method, parameter
   and return-type annotations plus the AnnotationDefault value (covers enum constants,
   class literals, nested annotations, arrays).
