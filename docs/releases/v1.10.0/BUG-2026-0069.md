## Solution Implemented (2026-06-10, residual (a) branch-scoped declaration hoisting — tags BUG-2026-0069-20260610-16..17)

New transform pass `BranchVarHoister` (modeled on `SwitchVarHoister` / BUG-2026-0080), wired into
the structured pipeline immediately after `SwitchVarHoister`. Without LVT the decompiler declares a
slot at its first store; when that store is inside an if-branch the declaration lands there
(`if (c) { String r = "x"; } else { r = "y"; } return r;`) and the other-branch / post-if
references do not resolve. The pass hoists a plain declaration (`String r;`) before the `if` and
demotes the in-branch declarations to assignments.

Two shapes are covered:
- **If/else**: a top-level `Type v = expr;` in one branch whose name is used in the other branch
  and/or after the if. Fires only when the other branch's first touch is a definite,
  type-compatible write (plain `v = expr` / type-identical re-declaration, including through
  else-if chains via both-branches-write unification) — a read-before-write or mixed/partial
  write bails. Post-if reads additionally require definite assignment on every
  normally-completing path (other branch writes or ends abruptly; an initializer-less candidate
  decl — produced by a previous inner-level hoist — requires the branch remainder to write or end
  abruptly).
- **Plain if (no else)**: the original else became fall-through because the then-branch returns
  (`if (c) { int v = 10; return v + 1; } v = 20; return v + 2;` — the T7SlotReuse.reuse shape).
  Fires only when the FIRST post-if touch of the name is a definite type-compatible write, so the
  around-the-if path never reads an unassigned variable; otherwise it bails and keeps the current
  output (definite-assignment-invalid shapes are never produced).

Conservative guards (no behavior change when unproven): name already declared before the if; name
touched in the declaring branch before the declaration; any re-declaration of the name AFTER the
if (separate slot-reuse variable — hoisting would duplicate it); a re-declaration in either branch
that is not reachable through blocks/if-else chains (loop/try/switch/sync/label bodies) or has a
different declared type (type-disagreeing reuse → bail, the BUG-2026-0096 slot split already
covers the incompatible-store half); genuinely scoped same-name pairs (a declaration in EACH
branch, no post-if use) are left untouched. Loop induction variables live in `ForStatement` init,
never inside if-branches, and are structurally unaffected. The pass recurses into all nested
bodies (blocks, ifs, loops, labels, synchronized, try/catch/finally, switch cases) inner-first, so
multi-level shapes hoist stepwise (nested if/else → enclosing branch → method scope, verified by
H3Nested). The hoisted declaration carries the original generic signature (BUG-2026-0065 channel).
