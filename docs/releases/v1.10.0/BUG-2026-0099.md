# BUG-2026-0099: module-info `requires transitive` / `requires static` modifiers dropped

**Type**: Bug
**Status**: CLOSED (v1.10.0)
**Severity**: MEDIUM
**Created**: 2026-06-10
**Resolved**: 2026-06-10
**Cluster**: `module-requires-flags` (Java 9+ coverage)

## Description

Decompiling a `module-info.class` loses the `requires` modifiers: `requires transitive java.sql` is emitted as plain `requires java.sql`, and `requires static` would be dropped the same way. Semantic loss: consumers of the recompiled module lose implied readability (`transitive`) / optional-at-runtime (`static`) semantics.

Repro (verified 2026-06-10):
```java
module testmod {
    requires transitive java.sql;   // decompiles to: requires java.sql;
    ...
}
```
The rest of the module declaration (exports/exports-to/opens/uses/provides) round-trips correctly. Cosmetic side note: the implicit `requires java.base` (ACC_MANDATED) is emitted explicitly — legal but noisy.

## Technical Analysis

The data is fully present in the class file (Module attribute, JVMS 4.7.25: `requires_flags` with ACC_TRANSITIVE=0x0020, ACC_STATIC_PHASE=0x0040, ACC_MANDATED=0x8000) and is **parsed** by the model — `ModuleAttribute.Requires` carries `public final int flags` (`model/classfile/attribute/ModuleAttribute.java:42-44`). The flags are then discarded in the converter: `ClassFileToJavaSyntaxConverter.java:245-248` copies only name/version into `JavaSyntaxResult.moduleRequires` (`List<String[]>` — `[name, version]`, `JavaSyntaxResult.java:57`). The writer prints a bare `requires` (`JavaSourceWriter.java:985-996`).

### Suggested Approach

1. Extend the `String[]` rows (or replace with a small holder) to carry the flags: `[name, version, flags]`.
2. In `JavaSourceWriter` requires-loop (:985-996): emit `transitive ` when (flags & 0x0020) != 0 and `static ` when (flags & 0x0040) != 0, after the `requires` keyword.
3. Optionally skip the row entirely when (flags & 0x8000) != 0 and name == `java.base` (mandated implicit requires).

### Affected Modules

- `service/converter/ClassFileToJavaSyntaxConverter.java` (:245-248)
- `service/converter/JavaSyntaxResult.java` (:57)
- `service/writer/JavaSourceWriter.java` (:985-996)

### Estimated Effort

LOW

## Solution Implemented

Implemented exactly as suggested (change tags `BUG-2026-0099-20260610-1..3`):

1. `ClassFileToJavaSyntaxConverter` now copies `ModuleAttribute.Requires.flags` into the
   `moduleRequires` rows as a decimal string: row layout is `[name, version, flags]`.
2. `JavaSyntaxResult.moduleRequires` documented with the new row layout.
3. `JavaSourceWriter.writeModuleDeclaration` requires-loop now:
   - skips the row entirely when `(flags & 0x8000) != 0` (ACC_MANDATED) and the module is
     `java.base` (the implicit requires — emitting it was legal but noisy);
   - emits `transitive ` when `(flags & 0x0020) != 0` (ACC_TRANSITIVE) and `static ` when
     `(flags & 0x0040) != 0` (ACC_STATIC_PHASE) after the `requires` keyword.
   Missing/unparsable slot 2 degrades gracefully to flags=0 (plain `requires`).

### Files Modified

- `src/main/java/it/denzosoft/javadecompiler/service/converter/JavaSyntaxResult.java` -
  `moduleRequires` row layout `[name, version, flags]` (tag -1).
- `src/main/java/it/denzosoft/javadecompiler/service/converter/ClassFileToJavaSyntaxConverter.java` -
  carry `req.flags` into the row (tag -2).
- `src/main/java/it/denzosoft/javadecompiler/service/writer/JavaSourceWriter.java` -
  honor flags in the requires-loop: mandated-java.base skip + `transitive`/`static` modifiers (tag -3).

### Test Case

- Fixtures: `/tmp/modtest` (testmod: `requires transitive java.sql`, plain
  `requires java.logging`) and `/tmp/modtest2` (staticmod: `requires static java.compiler`,
  `requires transitive java.logging`).
- Verifies (evidence, 2026-06-10):
  - Decompiled testmod module-info shows `requires transitive java.sql;`, keeps plain
    `requires java.logging;`, and no longer shows `requires java.base;`.
  - Decompiled staticmod shows `requires static java.compiler;` and
    `requires transitive java.logging;`.
  - Both decompiled module-info.java recompile cleanly with
    `javac -d out --module-source-path src -m <module>` (testmod together with its
    original package sources).
  - Round-trip flag proof: `javap -v` on the **recompiled** testmod module-info shows
    `"java.sql" ACC_TRANSITIVE` (and the recompiler re-adds the mandated
    `"java.base" ACC_MANDATED` automatically).
  - Full matrix sweep unchanged: total=57 clean=41 fail=16 crash=0, identical failure
    list to the pre-change baseline.
