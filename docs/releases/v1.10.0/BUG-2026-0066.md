# BUG-2026-0066: Switch-expressions not reconstructed (per-case yielded value dropped)

**Type**: Bug
**Status**: CLOSED (v1.10.0)
**Severity**: HIGH
**Created**: 2026-06-08
**Resolved**: 2026-06-10

## Description
A `switch` expression (`int x = switch(d){case A -> 1; ...}`) decompiles to a statement switch whose case values are lost; the method silently returns a constant. Corpus J14SwitchExpr.

See `docs/reports/report-decompilation-defect-analysis.md` (defect F03) for full root-cause, file:line and
suggested approach.

## Solution Implemented (partial, v1.9.0)
`StructuredFlowBuilder.tryBuildSwitchExpression` reconstructs a switch EXPRESSION when every arm (cases +
default) yields a simple value through a common `return` merge whose predecessors are exclusively the arms.
`JavaSourceWriter` now renders `switch (sel) { case L -> v; default -> v; }` (single-line). Covers
arrow-and colon-yield value switches (`oldStyleColonYield` correct).

## Re-verification (2026-06-10, construct-matrix gap analysis)

Sub-symptoms found on top of the partial fix: (2) block-body arms (`yieldBlock`) lose case values;
(3) exhaustive enum switch expressions degrade to a statement switch + recompile error;
(4) string switch expressions nest the dispatch inside the first hash case (missing-return recompile error);
(5) NEW wrong-code regression: store-merge form (`int x = switch(...); return x + 1;`) folded into
`return switch(...)`, silently dropping the post-switch computation.

## Solution Implemented (final, 2026-06-10)

All changes tagged `BUG-2026-0066-20260610-N`.

**Model** (`SwitchExpression.SwitchCase`, tags 1-2 + 6-7): added `bodyStatements` (straight-line
statements executed before the arm's value is yielded; when `value == null` the arm completes abruptly
via a trailing `ThrowStatement`) with accessors, and made `value` settable for boolean arm coercion.

**Flow builder** (`StructuredFlowBuilder`, tags 3-5 + 8-13 + 15 + 17-18):

1. **Commit by in-place substitution** (tags 3, 4, 10): the merge block is no longer consumed and
   `return switch(...)` is no longer hardcoded. Instead, the leaked arm value is identity-matched inside
   the merge's consumer statement and replaced with the reconstructed `SwitchExpression` in place
   (`substituteSwitchValue`): covers `return <v>`, `Type x = <v>`, `x = <v>`, and call arguments
   (`f(<v>)` / `return f(<v>)`, recursing through nested call arguments). A literal-return fallback
   handles constants the converter re-materialized (e.g. `iconst_1` -> `true`). The caller then
   continues normal flow at the merge block, so post-switch code is preserved — fixes sub-symptom (5)
   wrong-code store-merge regression.
2. **Block-bodied and throwing arms** (tags 8, 9, 11): `simpleSwitchExprArm` accepts arms with
   straight-line statements before the yielded value (`case X -> { int b = ...; yield b + 1; }`) and
   throwing arms (statements ending in `ThrowStatement`, no value). The synthetic exhaustiveness default
   of enum-ordinal switch expressions is emitted verbatim (`default -> throw new MatchException(null, null);`),
   which compiles on JDK 21+ and is runtime-identical.
3. **Nested switch-expression arms** (tags 11, 17): an arm block that is itself a switch whose arms all
   flow to the same outer merge reconstructs recursively (`case 1 -> switch (b) { ... };`), with inner
   arm PCs consumed and inner leaf values registered for the substitution identity scan.
4. **Boolean arm coercion** (tags 6-7, 15-16): when the merge consumer is boolean-typed (method returns
   `Z` — wired from the converter via `setMethodReturnsBoolean` — or the store target is boolean),
   int-constant 0/1 arm values become `false`/`true` (`return switch(d.ordinal()){ case 5, 6 -> true; ... }`).
5. **Selector correctness** (tag 5): prefer the block's saved `selectorExpression` (the exact expression
   popped by tableswitch/lookupswitch) over the last-statement heuristic, mirroring BUG-2026-0085-14.
6. **findSwitchMergePoint candidate exclusion** (tags 12-13): when counting break gotos, skip gotos that
   originate at/after a NEARER candidate (they belong to that candidate's downstream region). javac's
   string-switch lowering (hash lookupswitch + index dispatch tableswitch) had the hash switch's merge
   stolen by the dispatch arms' gotos (4 gotos to the ireturn beat 3 gotos to the dispatch entry), which
   nested the dispatch inside the first hash case and dropped the method tail — the missing-return
   recompile error of sub-symptom (4).
7. **Pattern-switch merge-bound exemption** (tags 4, 18): the new merge-bound bail (`merge beyond the
   current build bound`) exempts pattern switches: a guarded pattern switch lives inside a `while(true)`
   restart loop whose body bound always precedes the merge (kept DecompilerTest `GuardSw` and matrix
   `C_PatternSwitch` reconstructing; C_PatternSwitch went from FAIL(3) to clean).

**Writer** (`JavaSourceWriter`, tag 14): renders block-bodied arms (`case X -> { stmts; yield v; }`),
single-throw arms (`default -> throw new MatchException(null, null);`) and multi-statement throwing arms,
inline within the single-line switch-expression form. No trailing `;` after block arms (javac rejects it).

### Residual limitations (cosmetic / out of scope)
1. **String switch expressions** are emitted as two stages — the hash dispatch statement switch
   followed by `return switch (idxVar) { ... }` — instead of a single `switch (str)` expression.
   Compiles and is runtime-identical. Folding needs `StringSwitchReconstructor` to match a
   `return`-SwitchExpression sibling (today it only matches a sibling statement switch).
2. **Enum switch expressions** render as `switch (e.ordinal())` with int labels and the synthetic
   `default -> throw new MatchException(null, null)` kept verbatim, instead of enum-constant labels
   with no default. Compiles (JDK 21+) and is runtime-identical.
3. Merge consumers other than return/store/declaration/call-argument (e.g. `return switch(...) + 1`)
   and arms spanning multiple basic blocks (internal if/else without a straight-line yield block) fall
   back to the statement-switch path.
