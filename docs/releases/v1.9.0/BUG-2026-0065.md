# BUG-2026-0065: Lambda parameter naming — shadowing vs captured-variable references

**Type**: Bug
**Status**: RESOLVED
**Resolved**: 2026-06-08
**Severity**: HIGH
**Created**: 2026-06-08

## Description
Non-capturing lambda parameters are named `argN`, which collides with the enclosing method's `argN`
parameters → javac "variable arg0 is already defined in method ...". Affects most stream/lambda code
(corpus J8Streams, J8Lambdas).

## Technical Analysis
The synthetic `lambda$*` method body is decoded with default local names `argN`
(`ClassFileToJavaSyntaxConverter` ~line 847) and the reconstructed lambda parameter declaration reuses the
same names (~line 213 / ~line 2385). When the enclosing method also has `argN` parameters, the lambda
parameter shadows them (illegal in Java).

### Attempted fix (reverted)
Renaming synthetic lambda-body params to `lpN` removed the shadowing for **non-capturing** lambdas
(J8Streams 5→1) but **broke captured-variable references**: for a capturing lambda the body references the
captured slot by the synthetic param name, which previously matched the enclosing `argN` *by accident*.
Renaming to `lpN` made `of(String n){ return () -> n; }` emit `() -> lp0` with `lp0` undefined
(J9Interfaces, J8Lambdas capturing()). The accidental match was load-bearing for captures.

### Correct approach (not yet implemented)
At the lambda call site, substitute the captured arguments into the body (replace the first
`capturedCount` synthetic-slot references with the actual captured argument expressions) AND rename only the
lambda's *own* parameters to fresh, scope-unique names. This requires a recursive expression/statement
rewriter over the lambda body (rename/substitute `LocalVariableExpression` by slot). Deferred because the
rewrite touches every expression type and must be regression-tested across all lambda shapes.

### Affected Modules
- `service/converter/ClassFileToJavaSyntaxConverter.java` (lambda reconstruction, case 0xBA)

### Estimated Effort
MEDIUM-HIGH

See `docs/reports/report-decompilation-defect-analysis.md` (defect F11).

## Solution Implemented
Added a reusable `transform/AstLocalRewriter` (immutable-AST rewriter with an `onLocal` hook). When the
synthetic lambda method has no full LVT (default javac), the call site now (a) substitutes each captured
argument into the body (`argN` -> the captured argument expression, honoring the `this`-capture offset) and
(b) renames the lambda's OWN parameters to fresh `pN` names. Result: `filter(p0 -> ...)`,
`(p2, p3) -> p2 + p3 + var2 + this.field`. When the LVT names every parameter, the previous behavior is
kept. `syntheticParamNames` is now recorded only when the LVT is complete.

### Files Modified
- `service/converter/transform/AstLocalRewriter.java` (new)
- `service/converter/ClassFileToJavaSyntaxConverter.java` (lambda reconstruction + LVT-completeness gate)

### Result
J8Streams 5->1, J8Lambdas 5->3; no regression (J9Interfaces capturing `of()` stays correct). 0 crashes.

### Test Case
Covered by corpus J8Streams/J8Lambdas; `DecompilerTest` 18/19.
