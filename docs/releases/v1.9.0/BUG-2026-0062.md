# BUG-2026-0062: Array-init `dup` copy double-counted → varargs receiver corruption

**Type**: Bug
**Status**: RESOLVED
**Severity**: HIGH
**Created**: 2026-06-08
**Resolved**: 2026-06-08

## Description
`textblock.formatted(name)` decompiled to `new Object[]{name}.formatted(new Object[]{name})` — the
synthesized varargs array became BOTH the receiver and the argument.

## Solution Implemented
The array-init absorber (iastore..sastore) unconditionally re-pushed the `NewArrayExpression` although the
`dup` before each store already left a copy on the stack. It now re-pushes only when the copy was actually
consumed (`stack.isEmpty() || stack.peek() != nae`).

### Files Modified
- `service/converter/ClassFileToJavaSyntaxConverter.java`

### Test Case
Corpus J15TextBlocks now fully recompiles (0 errors).
