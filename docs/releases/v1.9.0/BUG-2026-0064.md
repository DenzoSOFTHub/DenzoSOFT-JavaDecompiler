# BUG-2026-0064: instanceof pattern bindings not reconstructed (leaked / out of scope)

**Type**: Bug
**Status**: RESOLVED
**Severity**: HIGH
**Created**: 2026-06-08
**Resolved**: 2026-06-08

## Description
`if (o instanceof X x) { ... x ... }` decompiled to `if (o instanceof X) { X x = (X) o; ... }`; with slot
reuse across sibling branches the binding leaked or went out of scope → "cannot find symbol".

## Solution Implemented
New `transform/InstanceOfPatternReconstructor` (run after `BooleanSimplifier` on both pipeline paths):
when an `if`/`if-else` condition contains a pattern-less `instanceof X` whose operand matches a leading
`X v = (X) operand;` (declaration) or `v = (X) operand;` (reused slot) in the then-branch, it rewrites the
condition to `instanceof X v` and drops the cast. Each branch binds its own scoped variable.

### Files Modified
- `service/converter/transform/InstanceOfPatternReconstructor.java` (new)
- `service/converter/ClassFileToJavaSyntaxConverter.java` (wired into both pipelines)

### Test Case
Corpus J17Sealed `area()` now fully recompiles (J17Sealed 10 → 0).

### Known remaining
The `o instanceof X v && <uses v>` form (binding leaked into the `&&` with no cast-decl in the then-body)
needs decode-time LVT capture; tracked as part of defect F05.
