# BUG-2026-0078: break out of while(true) dropped → unreachable trailing return

**Type**: Bug
**Status**: CLOSED
**Severity**: CRITICAL
**Created**: 2026-06-09
**Resolved**: 2026-06-09

## Description
`while(true){ if(i>=len){} else {...} } return t;` — the `break` was lost (empty then-block) so the loop
never terminated and the trailing `return` was an "unreachable statement".

## Technical Analysis
A break compiles to `goto exitPc` where `exitPc == bodyStopPc`. The goto was consumed by the body's
`startPc == stopPc` boundary check before the break could be emitted; the labeled-break path only fired for
`target.startPc > stopPc`.

### Solution Implemented
`StructuredFlowBuilder`: a `whileTrueExitStack` records each while(true) loop's exit PC around the body
build; a forward goto whose target is on that stack emits a plain `break` (checked before the labeled-break
logic, so the innermost loop stays unlabeled).
