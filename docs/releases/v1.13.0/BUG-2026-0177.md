## Description

fcmpg/dcmpg push 1 for NaN, fcmpl/dcmpl push -1: the operator carries the variant so `(a <=> b) >= 0` from dcmpg is rendered `!(a < b)` (true for NaN), not `a >= b` (false for NaN).

## Technical Analysis

Transcribed from the change comments, in progressive order:

- **BUG-2026-0177-1** (`src/main/java/it/denzosoft/javadecompiler/service/converter/ClassFileToJavaSyntaxConverter.java:3471`): fcmpg/dcmpg push 1 for NaN, fcmpl/dcmpl push -1: the operator carries the variant so `(a <=> b) >= 0` from dcmpg is rendered `!(a < b)` (true for NaN), not `a >= b` (false for NaN).
- **BUG-2026-0177-2** (`src/main/java/it/denzosoft/javadecompiler/service/converter/transform/BooleanSimplifier.java:516`): `(a <=> b) OP 0` as a source comparison. For lcmp (no NaN) it is `a OP b`. fcmpg/dcmpg yield 1 for NaN, so the comparisons that are TRUE on 1 (`>`, `>=`) are the negation of the opposite source test; fcmpl/dcmpl yield -1, so `<`, `<=` are. javac emits exactly these shapes for `!(x < y)` and friends.
