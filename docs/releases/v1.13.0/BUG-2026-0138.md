## Description

A conditional back-jump is a do-while condition only when it is the LAST back-edge into its target. When a later block also jumps back there (`while ((c = read()) != -1) { ..; if (c == '\n') ..; }` compiles the inner `if` to a conditional jump straight to the header, followed by the body's `goto header`), the conditional is a `continue`-shaped branch inside a while loop. Taking it for a do-while condition wrapped the whole method in a bogus `do { ... } while (var1 != 10);` that referenced an out-of-scope local.

- **BUG-2026-0138-2** (`src/main/java/it/denzosoft/javadecompiler/service/converter/cfg/StructuredFlowBuilder.java:183`): When BOTH successors of the header conditional lead back to it, neither is the loop exit: the header's test is an `if` at the top of a `for (;;)` body, not a while condition.
- **BUG-2026-0138-3** (`src/main/java/it/denzosoft/javadecompiler/service/converter/cfg/StructuredFlowBuilder.java:1129`): Not a while(cond) loop when the branch target ALSO returns to the header (see BUG-2026-0138-2): `for (;;) { if (pos >= lim) {..} if (skipLF) {.. continue; } return cb[pos++]; }` was emitted as `while (pos >= lim) {..}` followed by the rest OUTSIDE the loop, silently losing the loop-back of the `continue` path. The while(true) machinery owns such headers.
- **BUG-2026-0138-4** (`src/main/java/it/denzosoft/javadecompiler/service/converter/cfg/StructuredFlowBuilder.java:711`): A backward goto to the innermost while(true) header is a `continue`. Emitting nothing was right only for the loop's physically last goto at the END of the body; nested in an if with code after it (`if (c) { pos++; continue; } return cb[pos++];`) the loop-back was silently lost and execution fell into the following code. A trailing `continue` of the body is removed again by the while(true) builder.
