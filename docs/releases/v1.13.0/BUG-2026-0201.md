# BUG-2026-0201: `--show-bytecode` prints no instructions

**Type**: Bug
**Status**: RELEASED
**Severity**: HIGH
**Created**: 2026-10-30
**Resolved**: 2026-10-30

## Description

With `--show-bytecode` (CLI) or *Options > Show Bytecode Info* (GUI) the decompiled source must carry
the disassembled instructions as comments before each statement. In the v1.13.0 working tree the
option produced plain source: not one instruction comment, for any class. v1.12.0 and commit
`e032be5` print them correctly, so this was a regression introduced by the uncommitted 2026-10-15..18
work, found while preparing the v1.13.0 screenshots.

```
$ java -jar java-decompiler-1.13.0.jar --show-bytecode Circle.class | grep -c "// [0-9]*:"
0        # v1.12.0 and e032be5: 8
```

## Technical Analysis

BUG-2026-0141 added a reference-collecting *dry render*: `JavaSourceWriter.process()` renders the
whole compilation unit once into a `NullPrinter`, to learn which types are actually referenced, and
then renders it for real. Both passes read the same `MethodDeclaration` objects.

The bytecode comments come from `method.bytecodeInstructions`, a `line -> instructions` map. The
writer stored a reference to that map in `currentBytecodeInstructions` and removed each line's entry
after printing it ("emit only once per line"). The dry render therefore emptied every method's map,
and the real render found nothing to print.

### Suggested Approach

Let the writer consume a copy of the map, so a render never mutates the model it renders. Turning the
option off in the dry render would also work, but leaves the writer non-idempotent.

### Affected Modules

`service/writer/JavaSourceWriter.java`

### Estimated Effort

LOW

## Solution Implemented

`currentBytecodeInstructions` is now a `HashMap` copy of `method.bytecodeInstructions`. The
once-per-line removal works on the copy, so the dry render and the real render each see the full map.

### Files Modified

- `src/main/java/it/denzosoft/javadecompiler/service/writer/JavaSourceWriter.java` - copy the
  per-method instruction map before emission (`BUG-2026-0201-1`)
- `src/test/java/it/denzosoft/javadecompiler/DecompilerTest.java` - new test (`BUG-2026-0201-2`)

### Test Case

- Test class: `DecompilerTest`
- Test method: `testShowBytecodeEmitted`
- Verifies: decompiling `offset += count` with `showBytecode=true` prints an `iadd` and a `putfield`
  instruction comment before `this.offset += ...`.
- Proven a real guard: FAILS on the pre-fix build (output has no instruction comments), PASSES on the
  fixed build and on commit `e032be5`.
