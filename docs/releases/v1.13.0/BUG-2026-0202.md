# BUG-2026-0202: for-each over a generic parameter rewritten to `for (Object x$e : xs)` plus a cast

**Type**: Bug
**Status**: RELEASED
**Severity**: MEDIUM
**Created**: 2026-10-30
**Resolved**: 2026-10-30

## Description

A for-each over a method parameter declared with type arguments lost its typed loop variable:

```java
// source
static double sum(List<Double> xs) {
    double total = 0;
    for (Double x : xs) { total += x; }
    return total;
}

// v1.13.0 working tree, all three debug modes
for (Object x$e : xs) {
    Double x = (Double) x$e;
    total += x;
}
```

The output compiles and behaves the same, but it is noise on one of the most common loops in Java
code. v1.12.0 and commit `e032be5` print `for (Double x : xs)`. Regression introduced by
BUG-2026-0159 in the uncommitted 2026-10-15..18 work; found while preparing the v1.13.0 screenshots.

## Technical Analysis

BUG-2026-0159 rewrites a typed loop variable over a *raw* `Iterable` into an `Object` loop plus a
cast, because `for (Shape s : rawList)` does not compile. `TypeCoercer.rawIterable()` decides
"raw" for a local by checking `genericLocals`, the set of locals declared with a generic signature.
That set was filled only from local variable declarations (LocalVariableTypeTable). Method
parameters never appear there, so every parameter looked raw, even when the method's `Signature`
attribute gives it type arguments. The Signature attribute is present in all three debug modes, which
is why `-g:none` was affected too.

### Suggested Approach

Feed the parameters whose Signature type has type arguments into `genericLocals`.

### Affected Modules

`ClassFileToJavaSyntaxConverter.java`, `transform/TypeCoercer.java`

### Estimated Effort

LOW

## Solution Implemented

`ClassFileToJavaSyntaxConverter.genericParamNames202()` splits the parameter list of the method
Signature into its top-level type signatures and returns the names of the parameters whose entry
contains `<`. The Signature omits synthetic and mandated parameters (BUG-2026-0168), so entries are
aligned with the last parameter names; a malformed Signature yields an empty set (claims nothing).
The set reaches `TypeCoercer` through a `ThreadLocal`, like the existing generic-field set, and is
added to `genericLocals`. A truly raw parameter (`List xs`) has no `<` in its entry and is still
rewritten by BUG-2026-0159.

### Test Case

- Test class: `DecompilerTest`
- Test method: `testGenericParamForEach`
- Verifies: in `-g`, `-g:source,lines` and `-g:none` the loop is `for (Double ...` and neither
  `for (Object ` nor `$e :` appears.
- Proven a real guard: all three cases FAIL on the pre-fix build and PASS after the fix.
- Runtime oracle: the fixture recompiles and prints the same output as the original (`3.5 3`) in all
  three modes.
