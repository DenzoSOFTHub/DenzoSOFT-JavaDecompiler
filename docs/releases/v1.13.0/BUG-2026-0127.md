# BUG-2026-0127: constant-label and array-class pattern switches left as a raw typeSwitch

**Type**: Bug
**Status**: RELEASED
**Severity**: HIGH
**Created**: 2026-09-06
**Resolved**: 2026-09-07
**Parent/related**: split from BUG-2026-0123 — this is the half that was fixed in v1.13.0; the
guarded form is BUG-2026-0128.

## Description
After v1.12.0 rebuilt statement-form pattern switches, 7 of the 3,376 JDK 25 `java.base` classes still
emitted the raw `SwitchBootstraps.typeSwitch` dispatch with every arm value dropped. Measuring them
showed three distinct shapes rather than one:

| Shape | Example | Status |
|---|---|---|
| constant labels (`case "true"`, with `case null`) | `java/io/FilePermission` | **fixed here** |
| array-class labels (`case byte[] _`) | `jdk/internal/foreign/Utils` | **fixed here** |
| guarded arms (`case X x when g`) with an index restart | `sun/security/provider/NamedKeyFactory`, the `java/text/*Format` family | open — BUG-2026-0128 |

The first two were rejected by an over-broad guard, not by any real limitation.

```java
// FilePermission before: every arm value dropped, method returned an unconditional value
switch (SwitchBootstraps.typeSwitch(var1, var2)) { case 0: break; case 1: break; case -1: break; ... }
return false;
// after
return switch (var1) { case null -> false; case "true" -> true; case "false" -> false;
                       default -> throw new RuntimeException(...); };
```

## Technical Analysis
`StructuredFlowBuilder.unnamedPatternArm` rejected any bootstrap label starting with `"`, `-`, `[` or
a digit, on the assumption that only a plain class name could form an arm. But javac routes an
ordinary constant switch through `SwitchBootstraps` as soon as it has a `case null`, so string and
numeric labels arrive on this path routinely; and an array-class label is a perfectly ordinary type
pattern once its descriptor is parsed.

### Affected Modules
- `service/converter/cfg/StructuredFlowBuilder.java`

### Estimated Effort
MEDIUM

## Solution Implemented
Constant labels now build real constant cases: a quoted label becomes a `StringConstantExpression`,
and int/long/float/double labels are parsed into their constant expressions (`parseNumericLabel`).
Array-class labels are parsed from their JVM descriptor into an `ArrayType` (`parseArrayLabel`),
including multi-dimensional and object element types, and form an ordinary type pattern.

### Files Modified
- `src/main/java/it/denzosoft/javadecompiler/service/converter/cfg/StructuredFlowBuilder.java`
  - `unnamedPatternArm` accepts string, numeric and array-class labels
  - new `parseNumericLabel` and `parseArrayLabel`
