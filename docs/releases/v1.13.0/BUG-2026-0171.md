## Description

findBlockEnd's nested-conditional scan is not bounded by the then-region: when the then-body ends with a loop, the scan picked up the ELSE body's loop back-edge as a merge, walked into the else region and returned its header. hasElse came out false and the if-then path built the ELSE body as the (negated) then-body, silently dropping the whole then-branch (`if (t == 4) { r = false; for(..){..} } else { r = true; for(..){..} }` printed as `if (t != 4) { r = true; for .. }`; xerces RangeToken.match). The block that physically closes the then-region being a `goto merge` is the definitive if/else shape.
