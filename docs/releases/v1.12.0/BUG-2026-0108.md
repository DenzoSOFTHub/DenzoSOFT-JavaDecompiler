# BUG-2026-0108: pattern-switch labels stored as CONSTANT_Dynamic rendered as `case  _`

**Type**: Bug
**Status**: CLOSED
**Severity**: HIGH
**Created**: 2026-09-05
**Resolved**: 2026-09-06

## Description
javac stores some pattern-switch case labels as a `CONSTANT_Dynamic` constant-pool entry rather than
as a plain Class/String/Integer. The decoder read only the latter three kinds of bootstrap argument,
so the label was lost and the arm came out as `case  _ ->` — which does not compile.

This affects **qualified enum constants** (`case DayOfWeek.MONDAY`), a finalized Java 21 feature, and
the JEP 507 primitive-pattern previews (`case true` / `case false`).

```java
// before
return switch (var1) { case  _ -> "mon"; case DayOfWeek d -> "day " + d; ... };
// after
return switch (var1) { case DayOfWeek.MONDAY -> "mon"; case DayOfWeek d -> "day " + d; ... };
```

## Technical Analysis
Two separate defects had to be fixed:

1. **Label extraction.** In the `typeSwitch`/`enumSwitch` bootstrap decoder only
   `CONSTANT_Class`, `CONSTANT_String` and `CONSTANT_Integer` arguments were handled; anything else
   fell through to `getUtf8`, which returns null for a `CONSTANT_Dynamic` entry (tag 17), leaving a
   `/* case N */` placeholder.

2. **Arm construction.** The switch-arm builder treats a label as a TYPE pattern and appends a
   binding name. Feeding it a resolved constant produced `case DayOfWeek.MONDAY _ ->` — a binding
   after a constant, still uncompilable.

The condy shape was read from real bytecode rather than assumed:
```
Dynamic #12:invoke:Ljava/lang/Enum$EnumDesc;
  12: ConstantBootstraps.invoke
      arg0 = MethodHandle -> java/lang/Enum$EnumDesc.of(ClassDesc, String)
      arg1 = Dynamic #13  -> ConstantBootstraps.invoke + ClassDesc.of("java.time.DayOfWeek")
      arg2 = String "MONDAY"
```

### Affected Modules
- `service/converter/ClassFileToJavaSyntaxConverter.java`
- `service/converter/cfg/StructuredFlowBuilder.java`

### Estimated Effort
MEDIUM

## Solution Implemented
`resolveCondyLabel` walks a `CONSTANT_Dynamic` label through its bootstrap method and renders it:
`ConstantBootstraps.invoke` + `EnumDesc.of` yields the enum constant (recursing into the nested
`ClassDesc.of` condy for the owner), `getStaticFinal` on `Boolean.TRUE`/`FALSE` yields `true`/`false`,
and `primitiveClass` yields the primitive type name. `CONSTANT_Long`/`Float`/`Double` labels now
render as suffixed literals instead of falling through.

Enum-constant labels keep the INTERNAL class name (`java/time/DayOfWeek.MONDAY`) so the arm builder
can emit a real static field access — which also lets the existing import collector see the class.
That builder now recognises constant labels (a dotted internal name, or `true`/`false`) and emits a
genuine constant `case` instead of a type pattern with a binding.

### Files Modified
- `src/main/java/it/denzosoft/javadecompiler/service/converter/ClassFileToJavaSyntaxConverter.java` —
  `resolveCondyLabel`, `methodHandleTargetName`, `methodHandleOwnerName`,

- `src/main/java/it/denzosoft/javadecompiler/service/converter/cfg/StructuredFlowBuilder.java` —

### Measured Result
| Gate | Before | After |
|---|---|---|
| `qualifiedEnumCase` probe | `case  _ -> "mon"` (uncompilable) | **`case DayOfWeek.MONDAY -> "mon"`** |
| Remaining errors mentioning the enum label | 1 | **0** |
| Construct matrix (three debug modes) | 55/53/54 | 55/53/54 (no regression) |
| `java.base` | 3,376/3,376, 0 errors | unchanged |

JDK 25 `java.base` contains no `CONSTANT_Dynamic` entries, so this fix does not move its numbers; it
matters for application code that uses qualified enum constants in pattern switches.
