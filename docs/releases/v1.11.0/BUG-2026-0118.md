# BUG-2026-0118: class-file major version > 69 (Java 26+) hard-rejected, producing no output

**Type**: Bug
**Status**: RELEASED
**Severity**: HIGH
**Created**: 2026-09-05
**Resolved**: 2026-09-05

## Description
Any class file with a major version above 69 (Java 25) was rejected with
"Unsupported class file version" and produced **zero output**, even though a Java 26 class file that
uses no new construct is structurally identical to a Java 25 one. Verified by patching the version
field of a real class file to major 70 and 99: batch mode counted an error and wrote nothing.

A decompiler is exactly the tool one reaches for when facing an artifact newer than one's own
toolchain, so refusing the whole class is the worst possible response.

## Technical Analysis
`ClassFileDeserializer.deserialize` threw whenever `majorVersion > MAX_SUPPORTED_MAJOR_VERSION`, and
that constant was pinned to `MAJOR_25`.

### Affected Modules
- `service/deserializer/ClassFileDeserializer.java`
- `util/StringConstants.java`

### Estimated Effort
LOW

## Solution Implemented
Added `MAJOR_26` (70) and `MAJOR_27` (71) and raised `MAX_SUPPORTED_MAJOR_VERSION` to `MAJOR_27`.
Above that the deserializer no longer throws: it parses on a best-effort basis, because the class file
format is stable across releases. Anything genuinely new still fails at the precise point that cannot
be read (an unknown constant-pool tag remains an error), which is far more useful than discarding the
whole class.

`MAX_KNOWN_FEATURE_MAJOR_VERSION` was added to record, separately from what can be *parsed*, the
highest release whose language features the pipeline actively reconstructs (Java 25).

No mutable state was introduced in the deserializer: it is a shared instance across `decompile()`
calls, so surfacing the version in the output header is left to IMP-2026-0073, which can read it from
the `ClassFile` the parser already populates.

### Files Modified
- `src/main/java/it/denzosoft/javadecompiler/util/StringConstants.java` — `MAJOR_26`, `MAJOR_27`,
  raised maximum, new `MAX_KNOWN_FEATURE_MAJOR_VERSION`
- `src/main/java/it/denzosoft/javadecompiler/service/deserializer/ClassFileDeserializer.java` —
  best-effort parse instead of throwing

### Test Case
Verified by patching the version field of a compiled class to major 70 (Java 26), 71 and 99: all three
decompile to correct source, where the pre-fix build emitted only a diagnostic report.
(A committed fixture cannot be produced without a JDK 26 javac; the check is documented here and in
the audit report section 2.6.)

### Measured Result
| Class file | Before | After |
|---|---|---|
| major 70 (Java 26) | no output, error counted | **decompiled correctly** |
| major 71 | no output | **decompiled correctly** |
| major 99 (arbitrary future) | no output | **decompiled correctly** |
