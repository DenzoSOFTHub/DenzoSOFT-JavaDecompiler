# BUG-2026-0106: LVT-driven pre-declarations duplicated by promoteUndeclaredAssignments

**Type**: Bug
**Status**: CLOSED
**Severity**: HIGH
**Created**: 2026-09-05
**Resolved**: 2026-09-05

## Description
On classes carrying a `LocalVariableTable` (javac `-g`, the Maven/Gradle default, so essentially every
production jar) the decompiler emitted two declarations for the same local:

```java
int sum;
int sum = 0;
```

which does not compile ("variable sum is already defined"). Measured: **10 of the 11 construct-matrix
recompile failures at `-g`**, and a duplicate-declaration site in about **30% of JDK 25 `java.base`
classes**.

## Technical Analysis
Two independent passes each decided the variable needed a declaration:
1. `decompileMethodBody` builds `preDeclarations` for LVT-named slots stored in two or more blocks and
   marks them in `declaredVars`, so the decoder emits `sum = 0` as a bare assignment.
2. `promoteUndeclaredAssignments` is seeded only with parameter names and AST declarations. It does
   not know about `preDeclarations`, which are prepended to the body only afterwards. It therefore
   sees `sum = 0` as an assignment to an undeclared local and promotes it to `int sum = 0;`.

`mergeDeclarationsWithAssignments` then cannot help, because it merges a declaration with an
assignment, not two declarations.

### Affected Modules
- `service/converter/ClassFileToJavaSyntaxConverter.java`

### Estimated Effort
LOW

## Solution Implemented
The set handed to `promoteUndeclaredAssignments` is seeded with the names of the pending
`preDeclarations`, so the assignment is left bare; the existing
`mergeDeclarationsWithAssignments` pass then folds `int sum;` + `sum = 0;` into `int sum = 0;`.

### Files Modified
- `src/main/java/it/denzosoft/javadecompiler/service/converter/ClassFileToJavaSyntaxConverter.java`
  - pre-declaration names added to the declared-name set before the promotion pass runs

### Test Case
- Test class: `DecompilerTest`
- Test method: `testNoDuplicateDeclaration`
- Verifies: a `-g`-compiled accumulator loop yields `int sum = 0` and never the bare `int sum;`
  (fails on the pre-fix build)

### Measured Result
| Gate | Before | After |
|---|---|---|
| Construct matrix `-g`, recompile-clean | 44/55 | **53/55** |
| `java.base` files containing a local re-declared while already in scope | 1,120 (8,055 sites) | **81** (128 sites) |
| Construct matrix default / `-g:none` | 55/55 / 53/55 | unchanged / 54/55 |

### Known residual
About 81 `java.base` files still re-declared a local after this fix alone. They are not slot-sharing cases (BUG-2026-0103
covers those): they come from the pre-declaration heuristic itself, which pre-declares any slot
assigned in two or more blocks even where a single declaration at first assignment would do.
Fixed by BUG-2026-0107 in the same release (down to 15 files / 28 sites).

### Measurement note
An earlier draft of these figures used a line-shape heuristic that also matched `return x;` as a
declaration and paired lines across different methods. The numbers above come from a scope-aware
scanner (brace-depth tracking, keyword exclusion) and are the ones to trust.
