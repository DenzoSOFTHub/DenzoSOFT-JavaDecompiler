# BUG-2026-0102: lambda block bodies emitted compound statements as /* inline stmt */

**Type**: Bug
**Status**: RELEASED
**Severity**: CRITICAL
**Created**: 2026-09-05
**Resolved**: 2026-09-05

## Description
A lambda whose body block contained anything other than an expression, a local declaration, a
`return` or an `if` had that statement replaced by the placeholder `/* inline stmt */;`. The code was
simply gone, and because the placeholder is a valid empty statement the result still compiled — silent
loss, the defect class this project ranks as the most severe.

Affected: `for`, `while`, `do`, `switch`, `throw`, `try`, `synchronized`, labeled statements,
`assert`, `yield`, `break`, `continue` and nested blocks.

Measured on JDK 25 `java.base`: **36 files, 66 sites**. Example from `java/lang/Module.java:1365`:

```java
.map(layer -> { Optional om = layer.findModule(dn); /* inline stmt */; Module m = (Module) om.get(); /* inline stmt */; return m; })
```

Both discarded statements were `assert` checks.

## Technical Analysis
`JavaSourceWriter.writeInlineLambdaStatement` handled only `ExpressionStatement`, `ReturnStatement`,
`IfStatement` and `IfElseStatement`. Everything else fell through to `writeInlineStatement`, whose
own coverage is limited to expressions, declarations and the multi-part blocks of a `for` header, and
which prints the placeholder for anything it does not recognise.

### Suggested Approach
Render the missing statement kinds. Routing them through the full `writeStatement` was considered and
rejected: that writer emits line-aligned multi-line output through `startLine`/`endLine`, and lambda
bodies are written inline inside an expression, so reusing it would have disturbed the line-alignment
machinery that is a headline feature of the default output mode.

### Affected Modules
- `service/writer/JavaSourceWriter.java`

### Estimated Effort
MEDIUM

## Solution Implemented
`writeInlineLambdaStatement` now renders every statement kind in the model, inline and on one line, to
match how lambda bodies are emitted: `throw`, `break`, `continue`, `while`, `do/while`, `for`,
`for-each`, `synchronized`, labeled statements, `switch` (with `case`/`default` labels), `try` (with
resources, multi-catch types and `finally`), nested blocks, `assert` and `yield`.

The placeholder branch is retained as the last resort, but no statement type in the model reaches it
any more.

### Files Modified
- `src/main/java/it/denzosoft/javadecompiler/service/writer/JavaSourceWriter.java`
  - `writeInlineLambdaStatement` extended to the full statement model

### Test Case
- Test class: `DecompilerTest`
- Test method: `testLambdaCompoundBody`
- Verifies: lambdas containing `throw`, `for`, `switch`, `synchronized`, `try/catch/finally` and a
  `while` loop all keep their bodies and emit no `inline stmt` placeholder (fails on the pre-fix
  build, which loses every one of them)
