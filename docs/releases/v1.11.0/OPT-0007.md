# OPT-0007: bytecode disassembly computed for every method regardless of --show-bytecode

**Type**: Optimization
**Status**: CLOSED
**Severity**: LOW
**Created**: 2026-09-05
**Resolved**: 2026-09-05

## Description
`BytecodeDisassembler.disassemble` ran for every method of every class even when `--show-bytecode` was
off and its result was discarded. JFR profiling of a 3,376-class batch attributed about 12% of CPU to
it (`decodeInstruction` 2.4% self, 12.1% inclusive).

## Technical Analysis
The disassembly was produced during method conversion, but the `showBytecode` flag lived in the
`configuration` map read only by the writer, so the converter had no way to know it was pointless work.

### Affected Modules
- `service/converter/ClassFileToJavaSyntaxConverter.java`

### Estimated Effort
LOW

## Solution Implemented
The converter reads the `showBytecode` flag from the message `configuration` in `process()` and skips
the per-method disassembly unless it was requested.

### Files Modified
- `src/main/java/it/denzosoft/javadecompiler/service/converter/ClassFileToJavaSyntaxConverter.java`
  - `showBytecodeRequested` field set in `process()`; disassembly call gated on it

### Test Case
Covered by the existing suite (output must be unchanged) plus a manual check that `--show-bytecode`
still emits instruction comments and that default output contains none.

### Measured Result
`java.base` batch (3,376 classes), three runs each: **2,150-2,342 ms** after, against **2,856-4,399 ms**
before. Output is byte-identical in default mode.
