# BUG-2026-0073: Nested lambda leaks as `Class::lambda$x$n` (synthetic-body ordering)

**Type**: Bug
**Status**: RESOLVED
**Severity**: HIGH
**Created**: 2026-06-08
**Resolved**: 2026-06-08

## Description
A lambda nested inside another lambda was emitted as a raw method reference to the synthetic method
(`J8Lambdas::lambda$nested$1`) instead of being inlined, because the synthetic-body map was populated
incrementally and the outer body was decoded before the inner body was registered.

## Solution Implemented
The synthetic-body decode loop now runs in TWO passes: the first registers every `lambda$` body, the second
re-decodes them with the full map available so nested lambdas inline.

### Files Modified
- `service/converter/ClassFileToJavaSyntaxConverter.java`

### Result
`forEach(p6 -> { Runnable var2 = () -> System.out.println(p6.intValue() + this.field); var2.run(); })`
(was `J8Lambdas::lambda$nested$1`).
