# BUG-2026-0133: `synchronized` dropped when its monitor temp is consumed as an instanceof binding

**Type**: Bug
**Status**: TO_ANALYZE
**Severity**: CRITICAL
**Created**: 2026-09-07

**Source**: `docs/reports/report-java25-and-beyond-analysis.md` section 2, Q5. Severity CRITICAL per
the report; no other source rates it.

## Description

`synchronized (x) { ... }` inside `if (x instanceof T)` loses the lock entirely, and gains a bogus
pattern binding. The output compiles and is unsynchronised.

```java
// java/lang/String.contentEquals, bytecode pc 14-28: aload_1; dup; astore_2; monitorenter; ...
if (cs instanceof StringBuffer n) {                 // lock gone, bogus binding `n`
    return this.nonSyncContentEquals((AbstractStringBuilder) cs);
}
```

Probe `SCRATCH/probe/src/P_SyncSlot.java`: 3/3 methods lose the lock in **all three debug modes**,
with no marker left behind. The `java.base` census lists 16 classes whose `synchronized (` count
differs from their `monitorenter` count (`String` 0/1, `Cipher` 0/2, `LoginContext` 0/1,
`DefaultProxySelector` 0/1, `Subject` 9/12, `VirtualThread` 7/9, `JarFileFactory` 5/7, and
`UnixAsynchronousSocketChannelImpl` 13/11, a fabrication).

BUG-2026-0101 was closed on "`__MONITORENTER__` markers 98 -> 0 files"; the locks are still lost, only
the marker is gone.

## Technical Analysis

`InstanceOfPatternReconstructor.tryBind` (:200-235) accepts a leading bare alias `v = operand;` in
the then-body as the pattern binding (`bareAlias`, added for BUG-2026-0067). The monitor temp store
(`dup; astore_2` -> `var2 = cs;`) is exactly that shape, so the store is consumed into
`cs instanceof StringBuffer var2` and removed from the body. `reconstructSynchronized` then finds a
`__MONITORENTER__` with no preceding `varX = lockExpr` (`extractLockFromTail` returns null, :5306)
and skips the marker; the exit markers are stripped as leftovers.

The two reconstructors run in the wrong order for this shape: `reconstructSynchronized` runs after
`InstanceOfPatternReconstructor`.

### Suggested Approach

In `tryBind`, refuse a bare alias whose next statement is a `__MONITORENTER__` marker, or more
generally one whose alias variable is never read in the then-body — a pattern binding that is never
read is not what javac emits. Prefer this to reordering the chains (local, no ordering change).
