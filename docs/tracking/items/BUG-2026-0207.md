# BUG-2026-0207: `--batch` skips nested archives, reports 0 classes for an APK, and exits 0 on failures

**Type**: Bug
**Status**: TO_ANALYZE
**Severity**: MEDIUM
**Created**: 2026-10-30

## Description

- `--batch` over a WAR, EAR or Spring Boot JAR does not descend into nested archives
  (`WEB-INF/lib/*.jar`, `BOOT-INF/lib/*.jar`, EAR modules). Their classes are not decompiled and the
  summary does not say they were skipped.
- `--batch` over an `.apk` decompiles 0 classes (DEX is not supported) without saying why.
- `--batch` exits with status 0 even when classes fail to decompile (`Main.java`, batch branch), so a
  script cannot detect a failed run from the exit code.

## Technical Analysis

Not analysed in code yet.

### Suggested Approach

Report skipped nested archives and unsupported DEX content in the batch summary; optionally add a flag
to recurse into nested archives. Exit non-zero when `Errors > 0`.

### Affected Modules

`Main.java`, `BatchDecompiler.java`

MEDIUM
