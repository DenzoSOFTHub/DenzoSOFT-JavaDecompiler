# BUG-2026-0096: No-LVT slot typing: boolean istore declared as int; slot reuse with incompatible types shares one variable

**Type**: Bug
**Status**: IN_ANALYSIS
**Severity**: MEDIUM
**Created**: 2026-06-10
**Cluster**: `local-slot-typing` (construct-matrix gap analysis, fix order #21)
**Parent/related**: BUG-2026-0069(a) partial; NEW for the boolean branch — umbrella BUG-2026-0080

## Description

Class of defect: decompile→recompile failure. Matrix classes affected: C_Unnamed.

- **C_Unnamed**: dec/C_Unnamed.java:28: error: incompatible types: boolean cannot be converted to int — 'int var3 = arg0.add(1);' (original: 'var _ = list.add(1);' in sideEffect)
- **C_Unnamed**: 5 errors in firstX(): dec/C_Unnamed.java:62 'incompatible types: int cannot be converted to Point' (var5 = var3.x()), :63 and :64 'Point cannot be converted to int' (int var6 = var5; int var4 = var5), :65 'int cannot be converted to Point' (var5 = var3.y()), :66 'Point cannot be converted to int' (var6 = var5) — one variable 'C_Unnamed.Point var5' is reused for int values.

## Technical Analysis

### C_Unnamed (confidence: HIGH)

Bytecode is 'invokeinterface List.add:(Ljava/lang/Object;)Z; istore_3'. The invoke decode correctly types the expression boolean (retType = parseType(retDesc) at ClassFileToJavaSyntaxConverter.java:2252-2254), but the istore cases pass defaultType=PrimitiveType.INT (ClassFileToJavaSyntaxConverter.java:1849-1851 and 1864-1866). storeLocal (ClassFileToJavaSyntaxConverter.java:2884) resolves the declared type as LVTT-signature -> LVT-descriptor -> defaultType; the class is compiled without -g so both maps are empty and INT wins. The RHS-type inference block (LIM-0002 change, ClassFileToJavaSyntaxConverter.java:2906) is guarded by 'type == ObjectType.OBJECT', so it only runs for astore and never consults value.getType()==BOOLEAN for istore. NOTE: not unnamed-specific — a named 'boolean ok = list.add(1)' compiled without -g hits the same bug.

### C_Unnamed (confidence: HIGH)

javac's record-pattern desugaring reuses dead slot 5 for unrelated typed temporaries: javap firstX() shows astore 5 at pc 16 and 33 (holds Point from Pair.a()/Pair.b()) then istore 5 at pc 39 and 57 (holds int from Point.x()/y()). The decompiler identifies variables purely by slot index: storeLocal (ClassFileToJavaSyntaxConverter.java:2884) names the var 'names.get(index)' else "var"+index (:2887) and gates declaration on declaredVars.contains(index) (Set<Integer> field at :1278, checked at :2929). Once slot 5 is declared 'C_Unnamed.Point var5', every later istore 5 emits 'var5 = <int expr>' with no type-compatibility check, and loads via pushLocal (:1802-1838) reuse the same name, so 'int var6 = var5' reads the Point-typed variable. Without -g there is no LVT to disambiguate slot reuse.

**Verifier correction**: declaredVars membership check is at line 2928, not 2929. Also note: fixing the RecordDeconstructionFolder dead-binding issue (see claim 3 correction) deletes these temps in firstX/onlyX entirely, so prioritize accordingly; the slot-reuse fix remains worthwhile for the general no-LVT case.

### Suggested Approach

ClassFileToJavaSyntaxConverter.storeLocal (:2884-2944): (1) when no LVT/LVTT info and defaultType==INT but value.getType()==BOOLEAN, declare boolean (one extra branch beside the ObjectType.OBJECT inference at :2906) — fixes 'int var3 = list.add(1)'. (2) Add a per-slot declared-type map beside declaredVars (:1278): on a store whose type category conflicts with the recorded declaration (reference vs int-category etc.), allocate a fresh name, update localVarNames so subsequent pushLocal loads resolve to it, and emit a new declaration — fixes C_Unnamed.firstX's Point/int slot-5 reuse generically. Note: pattern-switch-folding's dead-binding fix removes most of these temps in firstX/onlyX; this remains the general no-LVT safety net.

Per-finding fix details:

- In ClassFileToJavaSyntaxConverter.storeLocal (around line 2906): when no LVTT signature and no descriptor are available and defaultType == PrimitiveType.INT, and value.getType() == PrimitiveType.BOOLEAN, declare the local as boolean (boolean is the only int-category verifier type not assignable to int in source; byte/short/char widen fine so leave them as int). One extra branch beside the existing 'type == ObjectType.OBJECT' inference.

- Add per-slot declared-type tracking: a Map<Integer,Type> beside declaredVars (ClassFileToJavaSyntaxConverter.java:1278). In storeLocal, when the slot is already declared and the incoming store's type category conflicts with the recorded declared type (reference vs int-category, or boolean vs int, or long/float/double mismatch), allocate a fresh name (e.g. "var"+index+"a"), put it into localVarNames.put(index, freshName) so all subsequent pushLocal loads resolve to the new variable (decode is linear, and javac slot-reuse temporaries are linearly scoped), emit a new VariableDeclarationStatement, and update the recorded type. This fixes all 5 errors generically for any slot-reuse-without-LVT case, independent of record patterns.
