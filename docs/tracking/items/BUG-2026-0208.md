# BUG-2026-0208: GUI defects: Find never advances, archive tab "x" leaks the file, DEX tree inert, nested WAR shown as text

**Type**: Bug
**Status**: TO_ANALYZE
**Severity**: LOW
**Created**: 2026-10-30

## Description

Found while writing the v1.13.0 user manual:

1. **Find never advances.** `DecompilerGui.doFind()` calls `resetFind()` before every search, so Find
   always selects the first match and cannot step to the next one.
2. **Archive tab close leaks the file.** The "x" button of a top-level archive tab removes the tab but
   never calls `JarPanel.close()`, so the archive stays open. Only *File > Close Tab* (Ctrl+W) releases
   it.
3. **DEX Classes tree is inert.** The tree built for APKs has no double-click listener, so the DEX
   placeholder text is unreachable. The placeholder itself (`JarPanel.java`, "Use --deobfuscate with
   dex2jar") gives a meaningless hint.
4. **Nested WAR in an EAR** opens as raw bytes in a text tab instead of as an archive.

## Technical Analysis

Each is a small, local GUI issue in `gui/DecompilerGui.java` / `gui/JarPanel.java` /
`gui/CloseableTabComponent.java`.

### Suggested Approach

1. Reset the search position only when the search text or tab changes. 2. Route the tab "x" through
the same close path as Ctrl+W. 3. Add the listener and fix the hint. 4. Treat `.war` like `.jar` in
`openEntry`.

### Affected Modules

`gui/DecompilerGui.java`, `gui/JarPanel.java`, `gui/CloseableTabComponent.java`

### Estimated Effort

LOW
