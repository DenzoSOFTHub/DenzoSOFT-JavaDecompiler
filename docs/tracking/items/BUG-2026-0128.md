# BUG-2026-0128: guarded pattern switches with an index restart lose their arm values

**Type**: Bug
**Status**: IN_ANALYSIS
**Severity**: HIGH
**Created**: 2026-09-07
**Parent/related**: split from BUG-2026-0123 — the half that remains open; the fixed half is
BUG-2026-0127.

## Description
5 of the 3,376 JDK 25 `java.base` bodies still emit the raw `SwitchBootstraps.typeSwitch` dispatch
with every arm value dropped. All 5 are guarded pattern switches (`case X x when g`), where a failed
guard assigns the dispatch index and loops back to re-dispatch. `guardedPatternArm` does not match
them. All 5 carry the `PATTERN_SWITCH_NOT_RECONSTRUCTED` diagnostic.

Affected classes: `sun/security/provider/NamedKeyFactory` and the `java/text` formatters —
`CompactNumberFormat`, `DecimalFormat`, `NumberFormat`.

## Technical Analysis
The arm values travel on the operand stack to a merge that the flow builder does not rebuild.
`StructuredFlowBuilder.tryBuildSwitchExpression` matches only arms merging into a common return/store,
so the restart loop defeats it.

### What was already tried, and what NOT to repeat
One cause was identified and fixed-then-reverted: the binding can arrive as a bare assignment
(`s = (String) sel;`) rather than a declaration, because a binding name shared by two arms is
pre-declared ahead of the switch. Accepting that form did NOT reconstruct any additional switch, and
measuring it against the baseline showed it changed 170 files' output without reducing the raw count —
so it was removed rather than shipped. (That measurement is also what uncovered BUG-2026-0124: batch
output was non-deterministic, so part of that 170 was noise.)

### Suggested Approach
This is flow-builder work, not a transform. Recognise the `while (true) { switch (typeSwitch(sel,
idx)) }` retry scaffold, treat `idx = N; continue` as a failed guard (`when`), and take each arm's
value from the stack snapshot at its exit block — **the per-block exit-stack snapshots added by
BUG-2026-0051 are the likely source for those values**. `tryBuildSwitchExpression` has to model the
restart loop.

`PatternSwitchStatementReconstructor` deliberately DECLINES these shapes and should keep declining
them until the values can actually be recovered: rewriting them would produce valid-looking syntax
around a body still missing its values, and would silence the `PATTERN_SWITCH_NOT_RECONSTRUCTED`
diagnostic that currently reports them.
