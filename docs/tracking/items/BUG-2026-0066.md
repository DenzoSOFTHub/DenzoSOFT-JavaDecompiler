# BUG-2026-0066: Switch-expressions not reconstructed (per-case yielded value dropped)

**Type**: Bug
**Status**: IN_PROGRESS (value-arm subset resolved)
**Severity**: HIGH
**Created**: 2026-06-08

## Description
A `switch` expression (`int x = switch(d){case A -> 1; ...}`) decompiles to a statement switch whose case values are lost; the method silently returns a constant. Corpus J14SwitchExpr.

See `docs/reports/report-decompilation-defect-analysis.md` (defect F03) for full root-cause, file:line and
suggested approach.

## Solution Implemented (partial)
`StructuredFlowBuilder.tryBuildSwitchExpression` reconstructs a switch EXPRESSION when every arm (cases +
default) yields a simple value through a common `return` merge whose predecessors are exclusively the arms.
`JavaSourceWriter` now renders `switch (sel) { case L -> v; default -> v; }` (single-line). Covers
arrow-and colon-yield value switches (`oldStyleColonYield` correct).

### Files Modified
- `service/converter/cfg/StructuredFlowBuilder.java` (producer)
- `service/writer/JavaSourceWriter.java` (writer; replaced dead stub)

### Test Case
`DecompilerTest.testSwitchExpression`.

### Remaining
Block-body arms (`case X -> { ...; yield v; }`), throwing/exhaustive `default -> throw MatchException`
(enum/ordinal switches), store-merge (assignment) and string switch expressions still fall back to the
statement switch. These need YieldStatement arms + a SwitchExpression block-arm model extension.


## Re-verification (2026-06-10, construct-matrix gap analysis)

**Still reproduces**: YES

Item is marked IN_PROGRESS (partial fix in v1.9.0) and the verification matches that status, but the symptom has partially changed shape. (1) Simple value-arm return-merge switches (the resolved subset, e.g. oldStyleColonYield) are now correct. (2) Block-body arms (yieldBlock) still show the EXACT original symptom: statement switch with case values lost, method silently returns a constant. (3) Exhaustive enum switch expressions (arrow) now degrade to a statement switch where every label falls into `throw new MatchException(null, null)` plus an unreachable constant return — recompile error. (4) String switch expressions are now half-reconstructed but the switch expression is nested inside the hashCode-dispatch switch, producing a missing-return recompile error. (5) NEW wrong-code regression of the partial fix: store-merge form (`int x = switch(...); return x + 1;`) is folded into `return switch(...)` and the post-switch computation (+ 1) is silently dropped — compiles but is semantically wrong. Repro artifacts under /tmp/bugverify/BUG-2026-0066/ (sources, cls/, dec/, rebuild/).
