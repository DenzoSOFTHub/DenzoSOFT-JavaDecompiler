# BUG-2026-0057: StructuredFlowBuilder `visited` claim-tracker drops loop bodies / branch arms / if-chains

**Type**: Bug
**Status**: RESOLVED (dominant mechanism; sub-symptoms tracked below)
**Severity**: CRITICAL
**Created**: 2026-06-08
**Resolved**: 2026-06-08

## Description
On the default (legacy) flow path, ordinary control flow is silently corrupted: empty loop bodies
(`while(cond){}`), empty branch arms, boolean methods collapsed to a constant return
(`if(garbledCond){} return true;`), and if/else-if chains truncated to the first branch (→ "missing return",
non-compiling). Affects ≤Java-8 code present in nearly every method.

## Technical Analysis
`StructuredFlowBuilder.buildStatements()` threads a single `Set<Integer> visited`
(`StructuredFlowBuilder.java:117-119`) through all recursion. Compound-boolean folding and ternary scanning
ADD blocks to `visited` purely to *claim/consume* them (486/497/522, 591-600, 1300-1302), but the recursion
guards at `146-150` treat a *claimed* block as *already emitted* and bail — so the loop-body builder
(Pattern 1) / then-else builder (Pattern 2) / merge continuation return empty.

### Suggested Approach
Separate "claimed during analysis" from "emitted". Either split `visited` into two sets (`claimed` used only
to prevent re-folding a condition/ternary block; `emitted` consulted by the 149-150 guards), or scope a
fresh child set per structured region and merge back only blocks actually emitted. JD-Core avoids this
entirely by physically reducing the CFG (each block belongs to exactly one region) — the converter comment
at `ClassFileToJavaSyntaxConverter.java:986-991` already contrasts the two.

### Affected Modules
- `service/converter/cfg/StructuredFlowBuilder.java`

### Estimated Effort
HIGH (regression-sensitive — must not regress the ~99.7% java.base compile rate)

See `docs/reports/report-decompilation-defect-analysis.md` (defect F06).

## Solution Implemented
Root cause was narrower and more concrete than the original analysis: the **`canFormTernary` probe mutated
the caller's `visited` set**. While probing whether a branch could form a nested ternary, it executed
`visited.add(condBlock.startPc)` and recursed, permanently marking every inspected conditional block as
"emitted". Probing a `if (a) return X; if (b) return Y; if (c) return Z; return W;` cascade (which is NOT a
ternary) therefore poisoned the 2nd/3rd condition blocks; the real continuation then saw them visited and
bailed, dropping every branch after the first (silent truncation + "missing return"). The same poisoning
emptied many loop bodies.

Fix: `canFormTernary` is now a pure probe — it uses its **own** cycle-guard set (`probing`) and only
**reads** the emission `visited` set. The actual ternary emission path (`buildTernaryExpression`,
Pattern 0) already adds the real blocks to `visited` independently, so emission is unaffected.

### Files Modified
- `service/converter/cfg/StructuredFlowBuilder.java` - non-mutating `canFormTernary(block, visited, probing)` overload

### Result
- Sequential `if`-cascades and `instanceof`-cascades are no longer truncated; empty `for`/`while` bodies
  are reconstructed (e.g. `buildLoop` now emits its full loop body).
- Regression set (decompiler's own 151 classes): emitted code **10947 → 17270 lines** (+6323 recovered),
  **0 decompile crashes**, no block duplication. This was by far the highest-leverage fix.
- Official `DecompilerTest`: 18/19 (the 1 failure is the pre-existing `BasicClass` `super()` expectation,
  unrelated to this change).

### Test Case
- Test class: `DecompilerTest`
- Test method: `testSequentialIfReturn` (three sequential `if (cond) return N;` + final `return 0;` — all four returns must be present)
- Verifies: the if-cascade truncation does not recur.

### Remaining sub-symptoms (separate follow-up, NOT the canFormTernary mechanism)
Recovering the truncated branches exposes pre-existing, distinct bugs that were previously hidden:
- boolean-returning method emitted as `if (cond) { return ...; }` with no final return (boolean→if-structure).
- `while (true)` body reconstruction and `finally`-with-return still drop statements in some shapes.
- recovered `instanceof`/pattern branches surface the binding-scope bug (defect F05) and pattern-switch
  decode (defect F04). These are tracked separately; this item covers the `visited`-poisoning truncation.
