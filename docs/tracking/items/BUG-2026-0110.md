# BUG-2026-0110: anonymous classes lose fields, initializers and generic supertype arguments

**Type**: Bug
**Status**: IN_ANALYSIS
**Severity**: HIGH
**Created**: 2026-09-05
**Source**: `docs/reports/report-java25-plus-audit.md` §BUG-2026-0110 (audit of 2026-09-05, v1.10.0
baseline). Ranked #10 in that report's "IMPLEMENT FIRST" table.

## Description
Three distinct losses in anonymous class emission:
1. **Fields and their initializers are dropped.** `new Comparator() { int cnt = cap; public int compare(...) { this.cnt += 1; ... } }` emits the methods but not `int cnt = cap;` — the body then references a field that was never declared.
2. **Generic supertype arguments are lost**: `new Comparator<String>() {...}` prints as `new Comparator() {...}`.
3. **An anonymous class inside a lambda is not inlined at all**, emitted as a reference to the synthetic class: `() -> new P_Lambdas._1(k)`.

Evidence (audit workspace, not in the repo): `probe/dec/P_Generics.java:118-124` for (1) and (2) —
`javap P_Generics$1` confirms `int cnt;` exists, the Signature attribute is present, and `<init>`
contains the `putfield cnt`. `P_Lambdas.lambdaWithAnon` for (3).

## Technical Analysis
Root cause, as recorded by the audit against v1.10.0 line numbers:
- `JavaSourceWriter.java:3290-3312` inlines `anonResult.getMethods()` only (loop at :3302), so `<init>` — where field initializers live — is skipped entirely.
- The display name comes from `anonymousClassDisplayNames` (:97-110), which uses the ERASED supertype name and ignores `inner.getSignature()`.
- Lambda bodies take the inline path of BUG-2026-0102, which never reaches the `NewExpression` anonymous branch.

**Re-verified 2026-09-07** against the current tree: `anonymousClassDisplayNames` is still populated
from `TypeNameUtil.simpleNameFromInternal(ifaces[0])` / `inner.getSuperName()` at
`JavaSourceWriter.java:108-110` — the erased name, no signature parse. The methods-only inline loop
is still present. Line numbers elsewhere in this item are the audit's (v1.10.0) and have shifted.

### Suggested Approach
- Emit non-synthetic, non-`val$` fields with initializers recovered from `<init>`, reusing the same extraction as `writeCompilationUnit`'s instance-initializer logic (audit cites :330-600).
- Build the header from `SignatureParser.parseClassSuperType` / `parseClassInterfaceTypes` applied to `anonResult.getSignature()` instead of the erased name.
- Route lambda bodies through `writeStatement` (depends on BUG-2026-0102, released in v1.11.0).
