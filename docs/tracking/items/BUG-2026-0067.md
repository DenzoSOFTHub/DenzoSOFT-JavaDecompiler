# BUG-2026-0067: Java 21 pattern switch not reconstructed (raw SwitchBootstraps.typeSwitch leaks)

**Type**: Bug
**Status**: IN_PROGRESS (sealed/no-guard subset resolved)
**Severity**: HIGH
**Created**: 2026-06-08

## Description
`switch` over patterns leaks `switch (SwitchBootstraps.typeSwitch(...))`, leaked case bindings and `when`-guard retry loops. Corpus J21SwitchPattern (20), J21RecordPattern (54).

See `docs/reports/report-decompilation-defect-analysis.md` (defect F04) for full root-cause, file:line and
suggested approach.

## Solution Implemented (partial)
`tryBuildSwitchExpression` now recognises `switch (SwitchBootstraps.typeSwitch(sel, idx))`: the real selector
is the first bootstrap arg, each arm `Type b = (Type) sel; <value>` becomes a `case Type b -> value`, and a
synthetic `default -> throw MatchException` is dropped (exhaustive). `SwitchExpression.SwitchCase` gained
pattern type/binding/guard fields; the writer renders `case Type b [when g] -> value`.

### Files Modified
- `model/javasyntax/expression/SwitchExpression.java` (pattern fields)
- `service/converter/cfg/StructuredFlowBuilder.java` (pattern arm + typeSwitch selector + MatchException default)
- `service/writer/JavaSourceWriter.java` (pattern case rendering)

### Result
J21SwitchPattern `area()` recompiles: `return switch (var2) { case Circle var4 -> ...; case Square var5 -> ...; case Rectangle var6 -> ...; };`. J21SwitchPattern 20 -> 16.

### Test Case
`DecompilerTest.testPatternSwitch`.

### Remaining
`when` guards (the typeSwitch restart `while(true)` loop), record-deconstruction patterns (nested), null
labels, and multi-statement arms still fall back to the (mangled) statement switch; one record-pattern case
also hits a DECODE_ERROR at the typeSwitch bootstrap. Tracked here.

## Update — guarded pattern switch + case null (session 5b)
`tryBuildSwitchExpression` now also reconstructs `case null`, and **guarded** arms: a conditional arm
`Type b=(Type)sel; if(cond){value} else {idx=M; goto loopHeader}` becomes `case Type b when <guard> -> value`
(guard oriented to the value path; `boolExpr != 0` simplified to `boolExpr`). A `while(true)` whose body is a
single return/throw (the typeSwitch restart loop after the arms are consumed) is unwrapped. J21SwitchPattern
`classify()` now compiles: `return switch (var2) { case null -> "null"; case Integer var4 when var4.intValue() < 0 -> "negative"; ... };`. J21SwitchPattern 16->14.

### Test
`DecompilerTest.testGuardedPatternSwitch`.

### Remaining
Record-deconstruction patterns (`case Point(int x, int y)`, nested `Line(Point(...),Point(...))`) — desugared
as 6+ nested `try/catch(Throwable)->MatchException` wrappers + component extraction + `if(1!=0)` artifacts —
are NOT yet reconstructed (J21RecordPattern 54). That is the largest remaining decompilation feature.

## Update — record-pattern scaffolding cleanup (session 6, stages 1+2)
New `transform/RecordPatternReconstructor` performs the safe structural cleanups of the Java 21
record-pattern desugar: (1) strips `try { ... } catch (Throwable t) { throw new MatchException(...); }`
wrappers down to the try body (the catch referenced a try-scoped binding and did not compile); (2) flattens
always-true `if (1 != 0) { ... }` guards. Wired before `InstanceOfPatternReconstructor`.

### Files Modified
- `service/converter/transform/RecordPatternReconstructor.java` (new)
- `service/converter/ClassFileToJavaSyntaxConverter.java` (wiring)

### Result
J21RecordPattern 54 -> 36, J21SwitchPattern 14 -> 13 (corpus total 88 -> 69). Record-pattern bodies are now
clean, readable `if (o instanceof Type t) { <component extraction>; <body> }`.

### Remaining (Stage 3)
Folding the component-accessor extraction (`Type t; b1 = t.comp1(); b2 = t.comp2(); ...`) into an actual
deconstruction pattern `instanceof Type(C1 b1, C2 b2, ...)` (with correctly-typed bindings and nested
record patterns) needs a record-pattern AST node + data-flow folding — the remaining large piece.

## Update — record deconstruction folding (session 6, Stage 3)
New AST node `model/.../expression/RecordPattern` (recursive: simple binding | nested pattern) carried by
`InstanceOfExpression` and `SwitchExpression.SwitchCase`. New `transform/RecordDeconstructionFolder` folds the
component-accessor extraction into a real deconstruction pattern: matches `subject.comp()` accessor heads,
drops dead temporaries via downstream-liveness, captures the live binding, descends recursively through
nested `if (scratch instanceof T sub)` checks, and resolves the binding type from a cast head (generic
erasure). `InstanceOfPatternReconstructor` extended to anchor bare-alias bindings (`Box v = o;`). The writer
renders `Type(comp, ...)` (recursive) and collects component-type imports.

### Files Modified

- `service/writer/JavaSourceWriter.java` (writeRecordPattern + imports)
- `service/converter/ClassFileToJavaSyntaxConverter.java` (wiring)

### Result (instanceof form complete)

- nested: `if (arg0 instanceof Line(Point(int var5, int var6), Point(int var7, int var8)))`

## Update — sealed-exhaustive statement-form folding + unnamed components (session 7, wave 4, 2026-06-10)

**Status**: IN_PROGRESS (transform-layer scope COMPLETE; precise flow-level residuals listed below)

### Solution Implemented (transform/ layer, tags BUG-2026-0067-20260610-30..50)

`TypeSwitchRecordFolder` (hunks 30–34):
- The synthetic `default: throw new MatchException(...)` arm of a sealed-exhaustive pattern switch is
  recognized (`isMatchExceptionThrow`) and skipped — no `default` arm in the output (the source had none).
- **Tail-arm reclaim**: in the sealed-exhaustive shape the LAST arm falls out of the switch (empty labeled
  case). The fold reclaims it from the post-switch statements (`Type v = (Type) subject; <deconstruction>;
  return <value>;`) and only commits when the reclaim provably absorbs the WHOLE tail
  (`ArmFold.flatWalk`/`consumed` coverage check). `FoldResult.absorbedNext` became a count.

`RecordDeconstructionFolder` (hunks 35–43):
- **Dead component → unnamed pattern**: when no copy of an extracted component is live AND the scratch slot
  is dead downstream (write-before-read, `scratchDeadFrom`), the fold emits `Type _` / `var _` instead of
  aborting (C_Unnamed.onlyX/firstX).
- **Accessor static type**: the accessor's declared return type (method descriptor) overrides an
  erased-to-Object copy slot (`Line(Point a, Point b)` instead of `Line(Object, Object)`).
- `ArmFold` exposes top-list consumption (`flatWalk`, `consumed`) for the tail-reclaim coverage proof.

`SwitchVarHoister` (hunks 44–48):
- Cross-case writes are type-checked (`typeAssignable`: primitive widening + wrapper boxing; reference
  hierarchy assumed compatible) before sharing one hoisted declaration; an incompatible top-level write is a
  slot REUSE and that case's occurrences are renamed (`name_cN`, first write becomes the declaration);
  entangled shapes (read-before-incompatible-write) are left untouched. Re-declarations of an
  already-hoisted name demote to assignment or rename.

### Residuals (precise, with ownership)
1. **FLOW-LEVEL REGRESSION (BUG-2026-0066 scope — uncommitted hunk BUG-2026-0066-20260610-4)**: guarded
   `when` arms leak as raw `while(true){switch(SwitchBootstraps.typeSwitch(...))...}` and the stack-carried
   arm values are LOST (unrecoverable by transform/). Root cause (instrumented): the new `mergeReachable`
   precondition in `StructuredFlowBuilder.tryBuildSwitchExpression` (~line 1559) bails when the typeSwitch
   restart back-edge wraps the switch in a `while(true)` region whose build bound (stopPc) precedes the
   merge `areturn`. At HEAD this shape folded (`DecompilerTest.testGuardedPatternSwitch` PASSES at HEAD,
   FAILS in the working tree). Suggested fix for the 0066 owner: keep accepting return-merges (restore
   `mergeBlock.isReturn()` as an alternative passing condition for the statements/mergeReachable checks) —
   a return merge is consumed by the fold itself, never continued into. Affected: C_PatternSwitch
   classify/size (3 matrix errors), J21SwitchPattern classify/recordPattern (6 corpus errors),
   testGuardedPatternSwitch.
2. **FLOW-LEVEL (open, 0067/0066 shared)**: unnamed type-pattern arms (`case Integer _ -> "int"`) have NO
   cast-bind statement; `patternArm` requires exactly one statement, so the fold bails and the statement
   fallback drops the arm values (C_Unnamed.kind, 2 matrix errors). Needs flow-level acceptance of
   0-statement bare-value arms, with the pattern type taken from the typeSwitch bootstrap static labels.
3. **BUG-2026-0096 (slot typing)**: `var _ = list.add(1)` → `int var3 = arg0.add(1)` (boolean call result
   stored in an int-typed slot) — C_Unnamed.sideEffect, 1 matrix error. Not a 0067 defect.
4. `DecompilerTest.testGuardedPatternSwitch` failure = residual 1 (regression introduced by uncommitted
   0066 hunks, must be green again before commit/release).
5. `DecompilerTest.testBasicClass` failure (missing `super()`) is pre-existing at HEAD 8be1c32 and
   unrelated to 0067.
