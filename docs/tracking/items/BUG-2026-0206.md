# BUG-2026-0206: A nested class that cannot be loaded is dropped without a diagnostic

**Type**: Bug
**Status**: TO_ANALYZE
**Severity**: MEDIUM
**Created**: 2026-10-30

## Description

When the outer class names a nested class (InnerClasses attribute) but the loader cannot supply
`Outer$Inner.class` (`canLoad` returns false), the nested type is left out of the output with no
warning. `INNER_CLASS_SKIPPED` is recorded only when loading *throws*. The same applies to
`CtClass.decompile()`, which hands the decompiler only the one class.

The output then looks complete while a type is missing, which is the silent class this project tries
to avoid.

## Technical Analysis

Not analysed in code yet. The inner-class loop in `ClassFileToJavaSyntaxConverter.process()` skips a
nested class whose bytes are unavailable instead of recording a diagnostic.

### Suggested Approach

Record `INNER_CLASS_SKIPPED <name> (not found by the loader)` in the class-level warning banner when a
member/local/anonymous class listed in InnerClasses cannot be loaded.

### Affected Modules

`ClassFileToJavaSyntaxConverter`, `api/classmodel/CtClass`

### Estimated Effort

LOW
