# BUG-2026-0091: Count-based finally dedup deletes trailing returns; normal-path inlined finally never deduped

**Type**: Bug
**Status**: RESOLVED
**Severity**: HIGH
**Created**: 2026-06-10
**Resolved**: 2026-06-10
**Cluster**: `finally-dedup` (construct-matrix gap analysis, fix order #11)
**Parent/related**: BUG-2026-0080 (umbrella, 'finally-unreachable'); relates BUG-2026-0056 — umbrella BUG-2026-0080

## Description

Class of defect: decompile→recompile failure. Matrix classes affected: C_Concurrency, C_Exceptions.

- **C_Concurrency**: Both javac errors: "/tmp/matrix/dec/C_Concurrency.java:41: error: missing return statement" (nestedSynchronized) and ":54: error: missing return statement" (synchronizedOnArg). In both methods the `return <value>;` inside a synchronized block is silently deleted (e.g. `return o.hashCode();` and `return counter + cache;` vanish, leaving an empty/junk synchronized body).

## Technical Analysis

### C_Concurrency (confidence: HIGH)

TryCatchReconstructor.removeDuplicatedFinally (src/main/java/it/denzosoft/javadecompiler/service/converter/transform/TryCatchReconstructor.java:872-895, called from :271 and :277-278) truncates the LAST `finallySize` statements of the try body purely by COUNT, never comparing them to the actual finally statements. Its type-only heuristic (:879-886) explicitly whitelists ReturnStatement as a 'typical finally statement'. For javac's synchronized desugar the catch-any handler decodes to finally=[__MONITOREXIT__ marker] (markers emitted at ClassFileToJavaSyntaxConverter.java:2781-2793), finallySize=1, and the inlined cleanup (monitorexit) PRECEDES ireturn, so the try body is [EXIT-marker, Return] — the truncation deletes the Return instead of the duplicated EXIT. Verified with an instrumented build: after StructuredFlowBuilder the statement lists still contain `Return: arg0.hashCode(...)` / `Return: this.counter + this.cache`; instrumenting removeDuplicatedFinally shows calls with finallySize=1 and bodies [Expr@52, Return@52] (synchronizedOnArg) and [Expr@37, Expr@37, Return@37] (nestedSynchronized) whose trailing Return is dropped. Downstream, reconstructSynchronized (ClassFileToJavaSyntaxConverter.java:3496-3561) then builds a SynchronizedStatement with no return, yielding the non-void method bodies javac rejects.

**Verifier correction**: Two immaterial nits: (1) the method body actually ends at TryCatchReconstructor.java:896, not :895; (2) the ireturn (pc 10 in synchronizedOnArg) is technically one instruction past the exception-table try range [4,10), but the decompiler's region grouping does place the Return statement inside the try body, as my instrumentation confirms, so the stated mechanism is accurate in practice.

### Suggested Approach

transform/TryCatchReconstructor.java: (1) removeDuplicatedFinally (:872-896) truncates the last finallySize statements by COUNT with a type-only whitelist that includes ReturnStatement — change call sites (:271, :277-278) to pass the actual finally statements and remove only a structurally matching tail, or the N statements immediately before a trailing Return/Throw (javac inlines finally before each exit). Prototype verified: C_Concurrency.synchronizedOnArg recompiles. (2) Add stripLeadingFinallyDuplicate for afterTry after :288 and drop unreachable afterTry remains when finallyBody ends in Return/Throw (C_Exceptions.finallyWithReturn 'unreachable statement'). (3) Fix filterFinallyBody (:790-822): do not strip the first handler statement as an exception store when removeInitialExceptionStore (:227) already removed it — required for wide-opcode fix to restore C_Exceptions.tryCatchFinally.

Per-finding fix details:

- In TryCatchReconstructor.java change removeDuplicatedFinally to remove statements only when they STRUCTURALLY MATCH the finally body: (1) change the two call sites (:271, :277-278) to pass ((BlockStatement) finallyBody).getStatements() instead of finallySize; (2) compare the trailing N body statements to the finally statements via a statement-signature helper (statement class + expression/initializer toString); (3) if the tail does not match but the body ends in a Return/Throw, compare the N statements immediately BEFORE that terminator (javac inlines finally code before each exit point) and remove those instead, keeping the return. Prototype implemented and verified: decompiled C_Concurrency recompiles with 0 errors and synchronizedOnArg becomes `synchronized (arg0) { return arg0.hashCode(); }` (the EXIT marker is correctly recognized as the duplicated finally, so the return folds inside the block). Equality matching is strictly more conservative than count-based truncation, so regression risk for ordinary try/finally is low; run the full corpus to confirm.

## Solution Implemented

All changes confined to `TryCatchReconstructor.java`, tagged `BUG-2026-0091-20260610-1..5`.

1. **Structural finally dedup** (`removeDuplicatedFinally`, tag -5): signature changed from
   `(List<Statement>, int finallySize)` to `(List<Statement>, List<Statement> finallyStmts)`;
   both call sites (tag -3) now pass `((BlockStatement) finallyBody).getStatements()`.
   Removal order:
   - Case 1: the trailing N statements structurally match the finally body -> remove them.
   - Case 2: the body ends in Return/Throw and the N statements immediately BEFORE the
     terminator match the finally body (javac inlines finally before each exit) -> remove
     those, keep the terminator. This is the case that fixes the synchronized desugar
     (finally = [`__MONITOREXIT__` marker], body = [EXIT-marker, Return]).
   - Case 3 (documented fallback, old count-based behavior minus the ReturnStatement
     whitelist): trailing N statements that are ALL plain ExpressionStatements are removed by
     count. Inlined copies often render differently from the decoded handler body (different
     synthetic var names), and a strict no-match-no-removal policy regressed 4 of 10
     decompiler-own round-trip classes; an expression-only tail can never swallow a
     trailing `return`/`throw`, so the original bug cannot reappear.
   - Otherwise: remove nothing.
   Structural matching = statement class + line-independent signature (expression /
   initializer rendering; method invocations rendered WITH their arguments since the plain
   `toString` elides them); compound statements (if/loops/blocks) never match (conservative).
2. **Normal-path dedup in afterTry** (tag -3): `stripLeadingFinallyDuplicate` removes a
   structurally matching finally copy at the START of afterTry; when the finally body itself
   ends in Return/Throw the try statement completes abruptly, so any afterTry remains are
   unreachable and are dropped (fixes C_Exceptions.finallyWithReturn "unreachable statement").
3. **filterFinallyBody** (tags -1, -2, -4): new overload
   `filterFinallyBody(List<Statement>, boolean exceptionStoreAlreadyRemoved)`; the caller now
   tracks whether `removeInitialExceptionStore` actually removed the store and, if so,
   filterFinallyBody no longer strips the first handler statement (previously a REAL finally
   statement could be silently deleted). Old single-arg method kept, delegating with `false`.
