# BUG-2026-0123: guarded / multi-label / constant-label pattern switches lose their arm values

**Type**: Bug
**Status**: TO_ANALYZE
**Severity**: HIGH
**Created**: 2026-09-06

## Description
The remaining half of BUG-2026-0109. Three pattern-switch shapes still emit the raw
`SwitchBootstraps.typeSwitch` dispatch, and unlike the statement form their arm VALUES are absent from
the statement tree, so no AST pass can rebuild them:

- **guarded / multi-label arms** (`case Integer _, Long _ ->`, `case X x when g ->`): javac emits a
  `while (true)` retry scaffold where a failed guard assigns the dispatch index and loops back. The
  arm values travel on the operand stack to a merge the flow builder does not rebuild.
- **constant-label switches** (`case "true" -> …` over a String selector, with `case null`):
  `java/io/FilePermission`, `java/text/CompactNumberFormat`, `DecimalFormat`, `NumberFormat`.

7 of 3,376 JDK 25 `java.base` classes, all flagged with `PATTERN_SWITCH_NOT_RECONSTRUCTED`.

## Technical Analysis
`StructuredFlowBuilder.tryBuildSwitchExpression` matches only arms merging into a common return/store.
`PatternSwitchStatementReconstructor` (added in v1.12.0) handles the statement form, and deliberately
declines these shapes: rewriting them would produce valid-looking syntax around a body that is still
missing its values, and would silence the diagnostic that currently reports them.

### Suggested Approach
Flow-builder work, not a transform: recognise the `while (true) { switch (typeSwitch(sel, idx)) }`
retry scaffold, treat `idx = N; continue` as a failed guard (`when`), and take each arm's value from
the stack snapshot at its exit block. The per-block exit-stack snapshots added by BUG-2026-0051 are
the likely source for those values.

### Affected Modules
- `service/converter/cfg/StructuredFlowBuilder.java`
