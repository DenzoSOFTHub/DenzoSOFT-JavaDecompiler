# IMP-2026-0063: Complete SWITCH-form record patterns on the JD pipeline (decode-once rework)

**Type**: Improvement
**Status**: IN_PROGRESS (foundation landed; core blocker deferred)
**Severity**: HIGH
**Created**: 2026-06-09

## Description
The SWITCH form of Java 21 record patterns (`J21RecordPattern.sum`, `J21SwitchPattern.recordPattern` — 32 of
the 44 remaining corpus errors) cannot be reconstructed on the legacy path: its eager single-pass decode
displaces the per-arm value (the value leaks after the switch, case values are lost). The JD-Core pipeline
(`cfg/jd/`) PRESERVES the desugar structure and is the correct home.

## Foundation landed (this item, flag-gated — no effect on the default legacy path)
- `JdFlowBuilder` BlockDecoder: see-through `TYPE_TRY_DECLARATION` predecessors so the accessor receiver's
  exitStack is carried across the synthetic per-accessor try region (`var4.start()` instead of
  `this.start()`). (BUG-2026-0064 tag.)
- JD post-processing now runs `RecordPatternReconstructor` + `RecordDeconstructionFolder` (parity with
  legacy) → J21RecordPattern under `-Ddenzo.jd.pipeline=true` went 38 → 21 errors.
- `RecordDeconstructionFolder.foldArm(subject, body)` — public entry point to fold a switch arm's
  deconstruction (ready for the arm folder).

## Core blocker (DEFERRED — the real work)
The JD pipeline decodes each basic block ONCE. A switch-EXPRESSION desugars its arms to push a value and
`goto` a SHARED `*return` merge. Decode-once gives that shared return block a single baked-in value (the
first arm's), and the goto-reducer collapses the per-arm value blocks. So case 1 / default lose their values.

A per-case `visited` scope was tried and rejected: it lets later arms re-emit the shared return but with the
first arm's (out-of-scope) value — strictly worse.

The correct fix is a JD-level switch-EXPRESSION reconstruction (the legacy `tryBuildSwitchExpression`
equivalent, built in the JD pipeline): duplicate the shared return-merge into each arm and RE-DECODE it with
that arm's operand stack, so each arm yields its own value; then fold each arm via `foldArm` into
`case Type(...) -> value`, add selective activation (run JD only for typeSwitch+MatchException methods, keep
legacy default), and finally handle the guarded arm (`when`, nested typeSwitch + restart loop).

HIGH (JD reducer/decoder rework; multi-step; per-step success uncertain).
