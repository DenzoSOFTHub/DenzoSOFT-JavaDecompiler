# BUG-2026-0119: unknown invokedynamic bootstraps decoded as lambdas or method references

**Type**: Bug
**Status**: IN_ANALYSIS
**Severity**: MEDIUM (silent misrender)
**Created**: 2026-09-05
**Source**: `docs/reports/report-java25-plus-audit.md` §BUG-2026-0119 (audit of 2026-09-05, v1.10.0
baseline). Code-reading finding — no failing fixture was built for it.

## Description
Any `invokedynamic` bootstrap with at least 3 arguments and a `MethodHandle` at `args[1]` is decoded
as a lambda or method reference, REGARDLESS of the bootstrap owner. A bootstrap from any other source
— a language runtime, an ORM, a generated dispatcher — is therefore rendered as Java lambda syntax
that has nothing to do with what the instruction actually does. The output can compile and be wrong,
with no diagnostic.

## Technical Analysis
The owner check `bsmOwner == LambdaMetafactory` gates only SAM inference, not the decision to take the
lambda branch at all. (Audit cites `Converter.java:3150-3260`, with the gate at :3231.)

**Re-verified 2026-09-07**: `"java/lang/invoke/LambdaMetafactory".equals(bsmOwner)` appears at
`ClassFileToJavaSyntaxConverter.java:3705` and :3746, but the fallback path at :3762 onward —
commented "Fallback: lambda without body / This is likely a lambda from LambdaMetafactory" — builds
lambda parameters and a lambda expression without re-checking the owner.

### Suggested Approach
Gate the lambda branch itself on owner `java/lang/invoke/LambdaMetafactory` (and `altMetafactory`, see
BUG-2026-0114). For any other owner, emit `<Owner>.<bsmName>(args...)` plus an `INDY_UNSUPPORTED`
diagnostic rather than inventing a lambda.

### Affected Modules
- `src/main/java/it/denzosoft/javadecompiler/service/converter/ClassFileToJavaSyntaxConverter.java`

### Estimated Effort
LOW

### Test Case (when fixed)
Needs a hand-built class file with a non-LambdaMetafactory bootstrap; javac will not produce one. A
`StringConcatFactory` bootstrap is the closest thing reachable from ordinary javac output and is worth
checking first — it must NOT regress into the `INDY_UNSUPPORTED` path.
