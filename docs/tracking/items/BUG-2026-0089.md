# BUG-2026-0089: Non-trivial record canonical constructor dropped as 'implicit' (RHS-blind triviality check)

**Type**: Bug
**Status**: IN_ANALYSIS
**Severity**: HIGH
**Created**: 2026-06-10
**Cluster**: `record-canonical-ctor` (construct-matrix gap analysis, fix order #9)
**Parent/related**: BUG-2026-0080 (umbrella, 'record canonical-ctor'); NEW dedicated item — umbrella BUG-2026-0080

## Description

Class of defect: decompile→recompile failure. Matrix classes affected: C_Records.

- **C_Records**: Silent semantic loss (no javac error, wrong runtime output): Temperature's custom canonical constructor `public Temperature(double celsius) { this.celsius = Math.max(-273.15, celsius); }` is omitted entirely from the decompiled record. Recompilation generates the implicit canonical ctor, so `new Temperature(-500)` keeps celsius=-500.0 instead of the clamped -273.15, changing demo()'s output.

## Technical Analysis

### C_Records (confidence: HIGH)

JavaSourceWriter suppresses 'implicit' record members: isImplicitRecordMember (JavaSourceWriter.java:1727-1739, applied at lines 566 and 896 for nested records) calls canonicalCtorIsTrivial (JavaSourceWriter.java:1779-1795), which classifies a constructor as trivial if every statement is super(), a bare return, or an assignment whose LHS is `this.<component>` — WITHOUT checking that the RHS is the matching constructor parameter. Temperature's ctor decodes to `super(); this.celsius = Math.max(-273.15, arg1);`; the LHS name 'celsius' is in compNames, so the Math.max assignment is skipped at lines 1786-1790, the ctor is deemed trivial, and the whole method is dropped — contradicting the comment at lines 1722-1726 ('no user code is ever silently dropped'). The same RHS-blind filter exists in writeCompactRecordConstructor's residual filter (JavaSourceWriter.java:1650-1654), which would strip a non-trivial trailing component assignment from a ctor that also has validation code. Range survives only because its trailing assignments really are `this.lo = lo; this.hi = hi`. Not covered by any of the prior cluster hypotheses.

**Verifier correction**: One trivial imprecision: the claim quotes the decoded RHS as `Math.max(-273.15, arg1)`; the writer actually renders the parameter as arg0 (the double occupies local slot 1, named arg0 in output). This does not affect the root cause or fix.

### Suggested Approach

JavaSourceWriter.canonicalCtorIsTrivial (:1779-1795) classifies 'this.celsius = Math.max(-273.15, arg0)' as trivial because it only checks the LHS component name. Fix: only skip 'this.<comp_i> = rhs' when rhs is the LocalVariableExpression of canonical parameter i (pass the MethodDeclaration in to map slots). Same RHS-blind filter in writeCompactRecordConstructor's residual filter (:1650-1654). When a non-trivial component assignment remains, emit a FULL canonical constructor (params renamed to component names via the :1635-1638 map, super() dropped) since compact ctors cannot assign fields. Restores the Temperature clamping silently lost today.

Per-finding fix details:

- In JavaSourceWriter.canonicalCtorIsTrivial (line 1779) and the residual filter inside writeCompactRecordConstructor (lines 1650-1654): only skip an assignment `this.<comp_i> = rhs` when rhs is a LocalVariableExpression resolving to the canonical parameter for component i (compare against method.parameterNames.get(i) / the parameter's local slot, mapping component order to parameter order — pass the MethodDeclaration into canonicalCtorIsTrivial to access parameterNames). When a non-trivial component assignment remains, the ctor is not trivial; and since a compact constructor cannot assign fields, writeCompactRecordConstructor must fall back to emitting a FULL canonical constructor — parameter list renamed to component names via the existing rename map (lines 1635-1638), residual statements including the field assignments, while still dropping the decoded `super()` statement (explicit super() is illegal in a record canonical constructor). Expected output: `public Temperature(double celsius) { this.celsius = Math.max(-273.15, celsius); }`.
