# BUG-2026-0068: Modern (Java 9+) try-with-resources not collapsed

**Type**: Bug
**Status**: RESOLVED (residuals documented below)
**Severity**: HIGH
**Created**: 2026-06-08
**Resolved**: 2026-06-10

## Description
TWR desugar without a synthetic finally is not recognised: resources retyped to Object, double close, undefined throw variable. Corpus J9Interfaces, ClassicConstructs. cf BUG-2026-0054/0056.

See `docs/reports/report-decompilation-defect-analysis.md` (defect F09) for full root-cause, file:line and
suggested approach.

## Solution Implemented (partial)
New `transform/ModernTwrReconstructor` collapses the Java 9+ desugar
`R r = init; try { body } catch (Throwable t) { r.close(); throw t; } r.close();` into
`try (R r = init; ...) { body }`. Wired after `TryCatchReconstructor`. The import collector now also scans
try-resource declarations (they were lost when the decls moved into the resource header).

### Files Modified
- `service/converter/transform/ModernTwrReconstructor.java` (new)
- `service/converter/ClassFileToJavaSyntaxConverter.java` (wiring)
- `service/writer/JavaSourceWriter.java` (import collection for try-resources + finally)

### Result
`ClassicConstructs.tryWithResources` -> `try (BufferedReader var2 = ...; BufferedWriter var3 = ...) { ... }`.

### Remaining
The effectively-final form (`try (a; b)` over pre-existing vars) is mangled at the flow-builder level
(undefined throw variable, `if (var==null)` close chains) and is NOT collapsed — needs deeper exception-graph
handling. Tracked here.

## Solution Implemented (2026-06-10, wave 5)

Three changes (tags `BUG-2026-0068-20260610-1..5`):

1. **Exception-table coalescing** (`TryCatchReconstructor.wrapWithTryCatch` + new
   `isHandlerProtectionEntry`): before grouping by `(startPc, endPc)`, drop compiler-generated
   handler-protection entries — an entry is dropped ONLY when (a) its `startPc` equals another
   entry's `handlerPc` (it starts AT a handler) AND (b) a different entry routes to the identical
   `(handlerPc, catchType)`. This kills the spurious inner try that trapped the resource
   declaration out of scope (`readOrDefault`'s `[20,38)->38 IOException`; `copy()`'s
   `[52,70)->70 Throwable`). Genuine nested user try regions never satisfy both conditions.
2. **Nested TWR collapse** (`ModernTwrReconstructor.recurse`): `reconstruct()` returns a NEW
   list whose result was discarded for nested bodies, so nested TWR shapes (inner resource of a
   multi-resource try) never collapsed. Block bodies are now mutated in place
   (`live.clear(); live.addAll(nb)`); try/catch/finally bodies are reached through the
   BlockStatement branch.
3. **Effectively-final single-resource form** (`ModernTwrReconstructor`): the desugar
   `T orig = init; Object copy = orig; try { body } catch (Throwable t) { copy.close(); throw t; }
   if (copy != null) copy.close();` now collapses to `try (T orig = init) { body }`
   (runtime-identical: same init/body/close/suppression order). Guarded by a conservative
   reference scanner: only fires when the synthetic copy is dead outside the desugar and `orig`
   is not used after the try (new helpers `guardedCloseVar`, `refersTo`, `exprRefersTo`,
   `containsWord` — unknown statement shapes conservatively count as references).

### Residuals (still open, need flow/region-level work outside these two files)
1. **Multi-resource effectively-final form** (`try (a; b)` over pre-existing vars): the
   synthetic copies (`aload; astore`) all map to the try-header source line, so the line-based
   region split in the converter scrambles statement order (copy decls land after the try,
   use-before-declaration closes). Statement-level reconstruction cannot soundly reorder this;
   needs exception-graph/region handling in `ClassFileToJavaSyntaxConverter`.
2. **Same-line multi-resource typed header** (`try (A a = x; B b = y)` written on ONE source
   line): both declarations share the try-header line so the region split cannot separate
   them; output is mangled. The common multi-line formatting (one resource per line, as in the
   matrix/corpus sources) collapses correctly (as nested TWR, runtime-identical close order).
3. **Effectively-final resource that is a method parameter** (no preceding local declaration to
   pull into the header): not collapsed; would require emitting the Java 9+ bare-identifier
   resource syntax in the writer.
