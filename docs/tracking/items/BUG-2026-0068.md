# BUG-2026-0068: Modern (Java 9+) try-with-resources not collapsed

**Type**: Bug
**Status**: IN_PROGRESS (typed-resource collapse resolved)
**Severity**: HIGH
**Created**: 2026-06-08

## Description
TWR desugar without a synthetic finally is not recognised: resources retyped to Object, double close, undefined throw variable. Corpus J9Interfaces, ClassicConstructs. cf BUG-2026-0054/0056.

See `docs/reports/report-decompilation-defect-analysis.md` (defect F09) for full root-cause, file:line and
suggested approach.

## Solution Implemented (partial)
New `transform/ModernTwrReconstructor` collapses the Java 9+ desugar
`R r = init; try { body } catch (Throwable t) { r.close(); throw t; } r.close();` into
`try (R r = init; ...) { body }`. Wired after `TryCatchReconstructor`. The import collector now also scans
try-resource declarations (they were lost when the decls moved into the resource header).

### Files Modified
- `service/converter/transform/ModernTwrReconstructor.java` (new)
- `service/converter/ClassFileToJavaSyntaxConverter.java` (wiring)
- `service/writer/JavaSourceWriter.java` (import collection for try-resources + finally)

### Result
`ClassicConstructs.tryWithResources` -> `try (BufferedReader var2 = ...; BufferedWriter var3 = ...) { ... }`.

### Remaining
The effectively-final form (`try (a; b)` over pre-existing vars) is mangled at the flow-builder level
(undefined throw variable, `if (var==null)` close chains) and is NOT collapsed — needs deeper exception-graph
handling. Tracked here.
