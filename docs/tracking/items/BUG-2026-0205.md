# BUG-2026-0205: Nested classes silently lost for classes under `WEB-INF/classes/` or `BOOT-INF/classes/`

**Type**: Bug
**Status**: TO_ANALYZE
**Severity**: HIGH
**Created**: 2026-10-30

## Description

For classes stored under `WEB-INF/classes/` (WAR) or `BOOT-INF/classes/` (Spring Boot fat JAR),
nested and inner types (records, interfaces, enums, inner classes declared inside a class) are missing
from the decompiled output. No warning or diagnostic is emitted. It happens in `--batch` and in the
GUI. Batch output also keeps the `WEB-INF/classes/` path prefix in the output tree.

Found while writing the v1.13.0 user manual: a WAR built from a class with nested records and a nested
sealed interface decompiled with the nested types absent and no banner.

## Technical Analysis

Not analysed in code yet. Probable cause: the loader keys keep the container prefix
(`WEB-INF/classes/com/x/Outer$Inner.class`), while the converter asks the loader for the internal name
`com/x/Outer$Inner`; the lookup fails and the nested class is dropped (see BUG-2026-0206 for why that
is silent).

### Suggested Approach

Strip the `WEB-INF/classes/` / `BOOT-INF/classes/` prefix when building the loader index (the GUI's
*Classes* tree already hides it), and write batch output under the package path.

### Affected Modules

`BatchDecompiler`, `gui/JarPanel.JarLoader`

LOW
