# BUG-2026-0112: boolean local initialized with `a > b ? 1 : 0` instead of the boolean expression

**Type**: Bug
**Status**: IN_ANALYSIS
**Severity**: MEDIUM
**Created**: 2026-09-05
**Source**: `docs/reports/report-java25-plus-audit.md` §BUG-2026-0112 (audit of 2026-09-05, v1.10.0
baseline).

## Description
A local declared `boolean` in the LocalVariableTable but initialized from an int-valued ternary is
emitted as `boolean ok = a > b ? 1 : 0;`, which does not compile. Recompile failure, observed at `-g`.

Evidence (audit workspace): `probe/dec/P_Structured.java:214`.

## Technical Analysis
`BooleanSimplifier` handles ternaries for boolean methods (:172), assignment right-hand sides (:220)
and declarations (:277) — but only when the variable is ALREADY known to be boolean. Here the LVT says
`Z` while the initializer expression is int-typed, and `storeLocal` does not reconcile the two, so
none of the three branches fire.

**Not re-verified since the audit.** The `-g` construct-matrix failure set has shrunk from 11 classes
to 2 (`C_RecordPattern`, `C_VarInference`) as of 2026-09-07, so this shape may no longer be reachable
from the matrix; it was found on a probe fixture that is not in the repo. First step is to rebuild a
fixture for it and confirm the defect still reproduces.

### Suggested Approach
In `storeLocal` / the `BooleanSimplifier` declaration branch: when the declared type is `boolean` and
the initializer is `c ? 1 : 0`, `c ? 0 : 1`, or a bare `0`/`1`, rewrite to `c`, `!c`, and
`false`/`true` respectively.

### Affected Modules
- `src/main/java/it/denzosoft/javadecompiler/service/converter/transform/BooleanSimplifier.java`
- `src/main/java/it/denzosoft/javadecompiler/service/converter/ClassFileToJavaSyntaxConverter.java` (`storeLocal`)
