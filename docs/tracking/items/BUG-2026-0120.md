# BUG-2026-0120: StructuredFlowBuilder recursion cap truncates silently

**Type**: Bug
**Status**: IN_ANALYSIS
**Severity**: MEDIUM (silent, rare)
**Created**: 2026-09-05
**Source**: `docs/reports/report-java25-plus-audit.md` §BUG-2026-0120 (audit of 2026-09-05, v1.10.0
baseline). Confirms OPT-0006.

## Description
When `buildFromBlock` exceeds `DecompilerLimits.MAX_RECURSION_DEPTH` (200) it returns without emitting
anything and WITHOUT recording a diagnostic. Statements are dropped from the method body and nothing
in the output says so. This violates the pipeline's stated principle that every truncation is a grave
error and must at minimum be reported.

**Re-verified 2026-09-07**, `StructuredFlowBuilder.java:249-253`:
```java
recursionDepth++;
if (recursionDepth > DecompilerLimits.MAX_RECURSION_DEPTH) {
    recursionDepth--;
    return;                      // no diagnostic, no marker, statements lost
}
```
`MAX_RECURSION_DEPTH = 200` at `DecompilerLimits.java:12`.

## Technical Analysis
The cap is a guard against unbounded recursion on complex CFGs (the batch thread pool already gives
its threads a 2MB stack for the same reason). The defect is not the cap, it is that hitting it is
indistinguishable from normal completion.

### Suggested Approach
Two options, and the cheap one is worth doing on its own:
1. **Low effort, immediate value**: throw a `FlowDepthExceededException`, catch it in `decompileMethodBody`, record `STRUCTURED_FLOW_FAILED` and fall through to the linear scan (the existing downgrade path; audit cites :1660-1668). The output becomes degraded-but-complete with a recorded diagnostic instead of silently short.
2. **Larger**: make `buildFromBlock0` iterative so the cap is not needed (this is OPT-0006).

### Affected Modules
- `src/main/java/it/denzosoft/javadecompiler/service/converter/cfg/StructuredFlowBuilder.java`
- `src/main/java/it/denzosoft/javadecompiler/service/converter/ClassFileToJavaSyntaxConverter.java`

### Estimated Effort
LOW for the diagnostic; MEDIUM-HIGH for the iterative rewrite.

### Test Case (when fixed)
A synthetic class with deeply nested blocks that trips the cap; assert the diagnostic appears and that
no statement present in the source is missing from the output. Verify the test FAILS on today's build
(today it produces short output with no diagnostic, so the assertion on the diagnostic is the guard).
