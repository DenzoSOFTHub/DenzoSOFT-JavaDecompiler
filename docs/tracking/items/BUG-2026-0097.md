# BUG-2026-0097: Local classes never loaded; anonymous-class val$ captures unmapped; member-inner synthetic outer param leaks

**Type**: Bug
**Status**: IN_ANALYSIS
**Severity**: HIGH
**Created**: 2026-06-10
**Cluster**: `inner-classes-captures` (construct-matrix gap analysis, fix order #22)
**Parent/related**: BUG-2026-0080 (umbrella, 'local classes / anonymous capture'); NEW dedicated items — umbrella BUG-2026-0080

## Description

Class of defect: decompile→recompile failure. Matrix classes affected: C_InnerClasses, C_InterfaceMethods.

- **C_InnerClasses**: 2 of 4 errors, both on dec line 16: "error: cannot find symbol / symbol: class _1Local / location: class C_InnerClasses" (twice, for the variable type and the constructor) on `C_InnerClasses._1Local var2 = new C_InnerClasses._1Local(this, arg0);` — the method-local class `Local` from `useLocalClass(final int multiplier)` is never declared anywhere in the output.
- **C_InnerClasses**: 2 of 4 errors: dec line 24 "error: cannot find symbol / symbol: variable captured" in `int var1 = captured + C_InnerClasses.this.outerField;` (inlined Runnable body) and dec line 34 "error: cannot find symbol / symbol: variable base" in `return base + arg0 + C_InnerClasses.this.outerField;` (inlined C_Computable body). The capture constructor argument is also silently dropped: the new-expression is printed as `new Runnable() {...}` with `()` while bytecode passes (this, arg0).
- **C_InnerClasses**: Wrong output (compiles, so not among the 4 errors, but breaks round-trip fidelity): member inner class ctor emitted as `MemberInner(C_InnerClasses arg0, int arg1) { Objects.requireNonNull(arg0); this.offset = arg1; }` and call site `new C_InnerClasses.MemberInner(this, arg0)` (dec lines 11-13 and 42-45). Original is `MemberInner(int offset)` / `new MemberInner(offset)`. Recompiling makes javac add its own hidden outer parameter, so the round-tripped ctor descriptor becomes (LC_InnerClasses;LC_InnerClasses;I)V instead of (LC_InnerClasses;I)V, and the leftover requireNonNull is dead code.
- **C_InterfaceMethods**: javac: '/tmp/matrix/dec/C_InterfaceMethods.java:33: error: cannot find symbol — symbol: variable n' — the inlined anonymous class body in Greeter.of(String arg0) emits 'return n;' but the enclosing method parameter is named arg0, so the captured-variable reference does not resolve.

## Technical Analysis

### C_InnerClasses (confidence: HIGH)

Local classes are never loaded into the AST. ClassFileToJavaSyntaxConverter.process() (src/main/java/it/denzosoft/javadecompiler/service/converter/ClassFileToJavaSyntaxConverter.java:63-74) loads inner classes only when (a) ic.outerClassName != null (member/nested, line 65) or (b) ic.outerClassName == null && ic.innerName == null (anonymous, line 70). A local class's InnerClasses entry (javap: `#51= #18; // Local=class C_InnerClasses$1Local`) has outer_class_info = null but inner_name = "Local", matching neither branch, so C_InnerClasses$1Local is never loaded/emitted (same gap in the recursion at lines 102-109). The use site is rendered regardless: the declared type via emitRef (service/writer/JavaSourceWriter.java:143-158; digit-leading part gets '_' prefix at 151-154) and the constructor via the non-anonymous NewExpression branch (JavaSourceWriter.java:2719-2728; '_' prefix at 2720-2724), yielding a self-consistent reference `C_InnerClasses._1Local` to a class that does not exist. Aggravating: ClassFileToJavaSyntaxConverter.java:295 (`if (field.isSynthetic()) continue;`) drops the val$multiplier/this$0 capture fields (flags 0x1010), and JavaSourceWriter.java:2558-2561 strips `val$` in bodies, so naively emitting $1Local as a nested member class would still not compile (`multiplier` unresolved in run()).

**Verifier correction**: Minor precision note only: in the non-anonymous NewExpression branch the displayName computed at 2720-2724 is passed to emitRef (line 2726), which for $-containing internal names recomputes the sanitized 'C_InnerClasses._1Local' itself at 143-158; both cited prefix sites exist but the emitRef path is the one that produces the final qualified form. Does not affect the verdict.

### C_InnerClasses (confidence: HIGH)

Two interacting mechanisms. (1) When inlining an anonymous class body at the new-site, JavaSourceWriter.java:2680-2718 always prints empty argument list `()` (line 2696), discarding the captured argument expressions, and the body's `getfield val$captured` is rendered by stripping the `val$` prefix to the bare original variable name (JavaSourceWriter.java:2558-2561, BUG-2026-0045-1). That only compiles if the enclosing scope still has a variable with the original source name. (2) The matrix classes are compiled without -g, so the enclosing method has no LocalVariableTable and its parameter is given the fallback name `arg0` (ClassFileToJavaSyntaxConverter.java:366-375, `paramNames.add("arg" + ...)`). Hence the inlined body references `captured`/`base` which exist nowhere. Verified the fix is feasible: the anon class's converted <init> AST contains the mapping assignments (standalone decompile of C_InnerClasses$1 shows ctor body `captured = arg1; Objects.requireNonNull(arg0);`), i.e. FieldAccessExpression(val$captured) = LocalVariableExpression(argN).

### C_InnerClasses (confidence: HIGH)

ClassFileToJavaSyntaxConverter builds constructor parameters straight from the descriptor (ClassFileToJavaSyntaxConverter.java:343-375) with no detection/stripping of the synthetic outer-instance first parameter of a non-static member/local class. The writer suppresses the synthetic `this.this$0 = arg` store (isSyntheticOuterAssign, JavaSourceWriter.java:2045-2050, BUG-2026-0066-1) but neither the JDK18+ `Objects.requireNonNull(outerArg)` preamble that javac emits before super() nor the parameter itself; and the non-anonymous NewExpression branch (JavaSourceWriter.java:2719-2728) passes all bytecode arguments through including the explicit `this` (ThisExpression filtering exists only in the anonymous branch, lines 2686-2693). Knowledge that the class is non-static inner is available (innerClassAccessFlags lacks ACC_STATIC; original this$0 field exists but is discarded by the synthetic-field skip at converter line 295).

**Verifier correction**: Minor wording note only: the leftover 'Objects.requireNonNull(arg0)' after round-trip is redundant rather than strictly dead code — it would still throw on an explicit null argument — but since all emitted call sites pass 'this', the characterization is functionally accurate.

### C_InterfaceMethods (confidence: HIGH)

Anonymous-class capture name mismatch between the val$ field and the enclosing local. (1) The class is compiled without -g, so static method Greeter.of(String) has no LocalVariableTable and the decompiler synthesizes parameter name 'arg0' (ClassFileToJavaSyntaxConverter.java:368 and :374, paramNames.add("arg"+i) fallback). (2) Bytecode: C_InterfaceMethods$Greeter$1 holds the capture in field 'val$n' (ctor does aload_1; putfield val$n), and name() does getfield val$n; areturn — 'n' survives only in the field name. The writer renders any val$-prefixed FieldAccessExpression by stripping the prefix and printing the bare name (JavaSourceWriter.java:2558-2561), producing 'return n;'. (3) At the new-expression site for the anonymous class, JavaSourceWriter.java:2686-2696 collects the constructor arguments (the LocalVariableExpression for arg0) into filteredArgs but then discards them — comment 'For anonymous class implementing interface, always use empty args' followed by printer.printText("()") — so the positional link between captured local arg0 and field val$n is never established, and neither the enclosing parameter is renamed to 'n' nor the body reference rewritten to 'arg0'. Verified: hand-renaming 'String arg0' to 'String n' in the decompiled file makes it recompile with zero errors.

**Verifier correction**: Minor nuance only: in this specific no-LVT case, ClassFileToJavaSyntaxConverter.java:374 (the while-loop top-up) is the operative line that synthesizes 'arg0', because lvt==null skips the loop containing line 368 entirely; line 368 is the fallback for when an LVT exists but lacks a slot entry. Both citations are real and contain the claimed logic, so this does not affect validity.

### Suggested Approach

Three sub-fixes in dependency order: (1) Load local classes: ClassFileToJavaSyntaxConverter.process (:63-74) and the BUG-2026-0059 recursion (:102-109) miss InnerClasses entries with outerClassName==null && innerName!=null; add that branch and emit the class (interim: as nested member '_1Local' with explicit synthetic args; faithful: inside the enclosing method via EnclosingMethod). (2) Capture substitution at the anonymous inline site (JavaSourceWriter :2680-2718, which today prints '()' and strips val$ blindly at :2558-2561): build val$field -> call-site-expression map from the anon <init> AST and ne.getArguments(), consult it when rendering val$ field reads — fixes both C_InnerClasses.useAnonymous and C_InterfaceMethods.Greeter.of ('cannot find symbol: n'). (3) Member-inner ctor: strip the synthetic outer-instance first parameter, the JDK18+ Objects.requireNonNull(outer) preamble (next to isSyntheticOuterAssign :2045-2050), and the leading 'this' argument at non-anonymous call sites (:2719-2728), applied consistently to declaration and call sites.

Per-finding fix details:

- Step 1 (load): in ClassFileToJavaSyntaxConverter.process() and the BUG-2026-0059 recursion in loadAndAddInnerClass, add a third condition for local classes: `ic.outerClassName == null && ic.innerName != null && ic.innerClassName.startsWith(thisClassName + "$")`; record on the JavaSyntaxResult that it is a LOCAL class plus its source name (ic.innerName). Step 2 (emit): faithful fix is to declare the class inside its enclosing method (located via the inner class file's EnclosingMethod attribute) as `class Local {...}`, strip the synthetic outer/val$ ctor params and fields, and rewrite the NewExpression to `new Local(<non-capture args>)` with captured refs resolved by the same val$->enclosing-name mapping as the anonymous-capture finding. A cheaper interim fix that makes recompile pass: emit the loaded $1Local as a nested member class named `_1Local` (matching emitRef's sanitization), keep the synthetic ctor params explicit (as already happens for MemberInner so `new C_InnerClasses._1Local(this, arg0)` type-checks), declare the val$ fields (suppress the converter:295 skip for local classes) and suppress the val$ stripping at JavaSourceWriter:2558 when writing a named local class so body refs use the declared field.

- Build a capture substitution map at the inline site in JavaSourceWriter's anonymous NewExpression branch (around lines 2680-2698): take anonResult's `<init>` MethodDeclaration, walk its body for assignments `this.val$X = argN` to get val$ field -> ctor param slot; align ctor param positions with ne.getArguments() (the bytecode call already supplies them in order, outer `this` included) to get val$X -> call-site Expression (here `arg0`); stash the map in a writer field scoped like currentResult (BUG-2026-0044-2 pattern) while writing the inlined body; then at JavaSourceWriter:2558-2561, if the current val$ field is in the map, writeExpression the mapped call-site expression instead of printing the stripped name. Complementary nicer-output option in the converter: when the mapped call-site expression is a plain parameter/local, rename that enclosing variable to the val$ name (recovers `captured`/`base`/`multiplier` and benefits the local-class finding too), with collision checks when one variable is captured under different names.

- For classes whose InnerClasses entry marks them non-static with an outer class (or that originally had a this$N field — record this in the converter before the line-295 synthetic skip): (1) in the converter or writer, drop the first ctor parameter when its type equals the immediately-enclosing class; (2) in writeMethod's constructor statement loop (next to the JavaSourceWriter.java:2048 isSyntheticOuterAssign check) also skip a leading `Objects.requireNonNull(<outerParam>)` ExpressionStatement; (3) in the non-anonymous NewExpression branch (JavaSourceWriter.java:2719-2728) drop the leading outer-instance argument (ThisExpression or matching-type expression) for such classes, mirroring the anonymous-branch filtering at 2686-2693. Must be applied consistently to declaration and all call sites in the same pass to stay compilable.

- Build a capture mapping when inlining an anonymous class body in JavaSourceWriter (NewExpression branch, ~line 2697, BUG-2026-0044 block). Derive ctor-param -> val$field mapping from the anon class's <init> MethodDeclaration in anonResult (its body is a sequence of 'this.val$x = paramN' field-assignment statements; map positionally), or fall back to matching the anon class's val$ field declaration order against filteredArgs (javac emits captures in that order after any this$0). Then either: (a) writer-local substitution — add a Map<String,String> capturedVarSubstitution field (same pattern as the currentResult field set for body inlining), populate it (val$ suffix name -> rendered name of the corresponding filteredArgs expression, e.g. 'n' -> 'arg0') around the writeMethod loop at JavaSourceWriter.java:2704-2711 with save/restore for nested anonymous classes, and at line 2560 consult the map before printing instead of blindly stripping val$; or (b) higher-fidelity rename — when the captured arg is a simple LocalVariableExpression whose name is synthesized (argN/varN), rename the enclosing method's parameter/local to the val$ suffix name (arg0 -> n) and update all its references, with a collision check; this is better done as a transform pass in service/converter/transform/ invoked from ClassFileToJavaSyntaxConverter where the enclosing method AST and inner-class results are both available. Option (a) alone guarantees compilability; (b) restores original source fidelity.
