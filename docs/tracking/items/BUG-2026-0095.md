## Technical Analysis

### C_InstanceofPattern (confidence: HIGH)

**Symptom**: javac: '/tmp/matrix/dec/C_InstanceofPattern.java:27: error: cannot find symbol — variable var3' in bothNonEmpty. Decompiled output is 'if (arg0 instanceof String && arg1 instanceof String) { String var4 = (String) arg1; return !var3.isEmpty() && !var4.isEmpty(); }' — the declaration of the first instanceof-pattern binding (original 'a instanceof String x') is dropped entirely: neither emitted as a pattern variable nor as a cast declaration, while the body still references it.

javac lowers 'if (a instanceof String x && b instanceof String y)' to: [instanceof arg0; ifeq 46] -> block pc7-16 [checkcast; astore_3; instanceof arg1; ifeq 46] -> body pc19+ [checkcast; astore 4; ...]. The compound-AND merge in StructuredFlowBuilder.matchConditionalPattern (src/main/java/it/denzosoft/javadecompiler/service/converter/cfg/StructuredFlowBuilder.java:503-539) detects the shared false target (pc 46) and merges the two tests into 'cond1 && cond2' using ONLY secondCond.condition (line 516-519); secondCond.statements — which after decoder.decodeBlock (lines 510-512) contains the decoded 'String var3 = (String) arg0;' from checkcast/astore_3 — is silently discarded. The same drop exists in the OR-merge chain at lines 541-562. Two downstream repairs normally mask this: (1) InstanceOfPatternReconstructor.bindAmpersand (service/converter/transform/InstanceOfPatternReconstructor.java:128-146, BUG-2026-0067 workaround) re-binds the variable only when it is used as a method receiver INSIDE the merged condition (this is why isLongString 'var2.length() > 5' and classify 'var2.intValue() > 0' survive); (2) tryBind (InstanceOfPatternReconstructor.java:194-245) fuses a then-body-leading cast, but findInstanceOf (lines 247-253) returns the LEFTMOST instanceof (arg0) while the first body statement casts arg1, so sameOperand at line 232 fails (it correctly fuses single-condition 'length'). In bothNonEmpty var3 is used only in the then-body, not the condition, so neither repair fires and the only definition of var3 is lost.

**Fix detail**: Fix at the source of the drop in StructuredFlowBuilder.matchConditionalPattern. In the AND-merge loop (StructuredFlowBuilder.java:514-523), before merging check secondCond.statements: (a) if empty, merge as today; (b) if every statement is a pattern-binding cast 'T v = (T) opnd' (VariableDeclarationStatement with CastExpression initializer, or AssignmentExpression equivalent) whose operand and type match the current rightmost conjunct's unbound InstanceOfExpression (compare LocalVariableExpression index and type descriptor, same checks as InstanceOfPatternReconstructor.sameType/sameOperand), rewrite that conjunct to a bound InstanceOfExpression(opnd, T, v) and proceed with the merge — producing 'arg0 instanceof String var3 && arg1 instanceof String'; (c) otherwise do NOT set compoundFound (refuse the && merge), yielding a nested if where the statements remain in the then-block and the existing tryBind pass fuses them safely — this also makes the merge sound for arbitrary side-effecting statements. Apply guard (a)/(c) to the OR-merge loop at lines 545-559 as well (OR cannot carry a definitely-assigned binding, so just require empty statements there). Secondary polish for full fidelity: make InstanceOfPatternReconstructor.findInstanceOf (lines 247-259) skip instanceof nodes with hasPatternVariable() and/or return all unbound candidates so tryBind can also fuse the then-body's remaining 'String var4 = (String) arg1;' into 'arg1 instanceof String var4'; this is optional since an explicit cast declaration compiles. Add a matrix/DecompilerTest case with two chained instanceof bindings where the first binding is used only in the body.

### C_RecordPattern (confidence: HIGH)

**Symptom**: 3rd javac error, in isDiagonal() (dec line 49): "cannot find symbol: variable var2" in `return 1 != 0 && var3 == var2;`. The whole method body is mangled: the y-component binding `var2 = var5;` (bytecode 46-48 istore_2) is silently dropped; synthetic `1 != 0` scaffolding leaks into the returned expression; the else branch is empty `{ }` and the trailing `return false;` is missing (latent "missing return statement" error once var2 is fixed). Original source: `return o instanceof Point(int x, int y) && x == y;` — a record pattern in boolean-EXPRESSION position.

isDiagonal has no typeSwitch indy, so it stays on the legacy StructuredFlowBuilder path (ClassFileToJavaSyntaxConverter.java:1059, :1150-1152). Two cooperating defects in StructuredFlowBuilder.matchConditionalPattern: (1) the compound-AND merge (StructuredFlowBuilder.java:503-539) merges the `iconst_1; ifeq 58` cond block @42 with the following cond block @46-51 (`iload 5; istore_2; iload_3; iload_2; if_icmpne 58`) using ONLY secondCond.condition (:516-519) and marking it visited (:520) — secondCond's decoded statements [`var2 = var5;`] are discarded, producing the undefined var2 (statements guarded by the first condition cannot legally be expression-merged, so the merge itself is unsound). (2) the ternary Pattern 0 (:564-681) then consumes the shared boolean producers @54 (iconst_1; goto 59) and @58 (iconst_0) plus the @59 ireturn merge exactly once (visited.add at :625-626, :634), emitting `return (1 != 0 && var3 == var2) ? 1 : 0` (BooleanSimplifier strips the ternary); when the OUTER `if (o instanceof Point)` (cond @0, falseTarget @58) later builds its else branch, @58 is already visited, yielding the empty else and losing `return false;` for all false paths. The leaked `1 != 0` survives because RecordPatternReconstructor only flattens always-true IF STATEMENTS (RecordPatternReconstructor.java:50-65, isAlwaysTrue :154-165), not constants merged inside an expression. Confirms the prior 'pattern in expression context' gap; NOT fixable by JD routing: forcing -Ddenzo.jd.pipeline=true yields `if (arg0 instanceof Point(int var3, int var2)) { if (var3 == var2) { return false; } }` — inverted condition and missing returns (JD value-merge defect), so the legacy fix is required.

**Fix detail**: Two coordinated changes in StructuredFlowBuilder.matchConditionalPattern: (1) guard the &&/|| merges (StructuredFlowBuilder.java:513, :524, :550) with `secondCond.statements == null || secondCond.statements.isEmpty()` — genuine short-circuit operands compile to statement-free condition blocks, so this only blocks the unsound merge; the @46 block then goes through Pattern 0/2 which DO emit condBlock.statements (:628-629), preserving `var2 = var5;` and producing `if (1 != 0) { var2 = var5; return var3 == var2; }` (the 1!=0 wrapper is already flattened by RecordPatternReconstructor). (2) fix the shared constant-return false-path: when an else/continuation target block is already visited but is a pure constant-push + ireturn chain (here @58 iconst_0 -> @59 ireturn), re-materialize `return false;` instead of emitting an empty else — either special-case in the else-body construction / buildFromBlock visited-skip, or pre-pass tail-duplicate legacy return-merge blocks analogous to cfg/jd/ReturnMergeTailDuplicator.duplicate (referenced at ClassFileToJavaSyntaxConverter.java:596). Result is verbose-but-correct nested ifs that recompile; optionally extend RecordDeconstructionFolder with a boolean-return fold to regenerate `return o instanceof Point(int x, int y) && x == y;`.


### Suggested Approach

StructuredFlowBuilder.matchConditionalPattern merges conditions using only secondCond.condition, silently dropping secondCond.statements — at the AND merge (:514-523), the first-loop OR branch (:524-537), and the second OR chain (:545-559). Fix: (a) merge as today only when secondCond.statements is empty; (b) when every statement is a pattern-binding cast matching the rightmost conjunct's unbound InstanceOfExpression (unwrap the '!= 0' wrapper — BooleanSimplifier runs later), rewrite to a bound 'x instanceof T v' and merge (fixes C_InstanceofPattern.bothNonEmpty); (c) otherwise refuse the merge so statements stay in a nested if. Also re-materialize shared constant-return blocks (iconst_0/ireturn) when the else target is already visited, restoring 'return false' in C_RecordPattern.isDiagonal (legacy boolean-expression record pattern).
