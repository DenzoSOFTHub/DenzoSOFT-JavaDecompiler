# BUG-2026-0203: Record-pattern switch EXPRESSION loses every arm value, with no diagnostic

**Type**: Bug
**Status**: TO_ANALYZE
**Severity**: HIGH
**Created**: 2026-10-30

## Description

A switch *expression* whose arms include a record deconstruction pattern decompiles to a
`while (true) { switch (var1) { ... break; } }` skeleton with no `return` and none of the arm values.
The output does not compile, and the method carries **no** `PATTERN_SWITCH_NOT_RECONSTRUCTED` (or any
other) diagnostic, so nothing in the output says the body is wrong.

Reproducer (fails to recompile in `-g`, `-g:source,lines` and `-g:none`):

```java
public class RecSwitch {
    sealed interface S permits A, B {}
    record A(int x) implements S {}
    record B(double w, double h) implements S {}
    static String f(S s) {
        return switch (s) {
            case A a -> "a" + a.x();
            case B(double w, double h) -> "b" + w + "x" + h;
        };
    }
    public static void main(String[] args) {
        System.out.println(f(new A(1)) + " " + f(new B(2, 3)));
    }
}
```

Output (`-g`): `while (true) { switch (var1) { default: throw new MatchException(null, null);
case RecSwitch.A a: break; case RecSwitch.B var4: double var9 = var4.w(); ... break; } }`, then
`variable a is already defined` / `this case label is dominated by a preceding case label` on
recompilation.

Not a regression of this release: v1.12.0 also fails on it (with a different broken shape — it emits
`return "a" + a.x();` after the loop). The guarded variant (`case Circle c when ...`) is BUG-2026-0128,
which at least carries the diagnostic.

## Technical Analysis

Not analysed yet. Observations:

- The statement-form record switch and the instanceof-chain form (`if (s instanceof B(double w,
  double h))`) both reconstruct correctly; the failure is specific to the value-producing form.
- The construct matrix `-g` failure of `C_RecordPattern` (`variable a is already defined in method
  describe(Object)`) has the same message and is probably the same defect; it is the known `-g`
  baseline failure.
- The missing diagnostic is a defect of its own: the quality gate that flags an unfolded record
  switch did not fire for this method.

### Suggested Approach

First make the method carry `PATTERN_SWITCH_NOT_RECONSTRUCTED`, so the output is honest. Then
reconstruct the value merge; this is the same value-merge work that BUG-2026-0128 and the JD
retirement (IMP-2026-0072) need, and should be done once, in the legacy builder.

### Affected Modules

`ClassFileToJavaSyntaxConverter` (pipeline selection / quality gate), `StructuredFlowBuilder`
(`tryBuildSwitchExpression`), `RecordPatternReconstructor`, `RecordDeconstructionFolder`.
