# BUG-2026-0069: Local decl/type loss: multidim arrays, ternary-to-declaration, local generics erasure

**Type**: Bug
**Status**: TO_ANALYZE
**Severity**: HIGH
**Created**: 2026-06-08

## Description
Multi-dim array initializers garbled; `var r = b?A:B` collapses to a constant; a re-used slot can emit an assignment with no declaration; local generic types erased. Corpus J10Var, ClassicConstructs.

See `docs/reports/report-decompilation-defect-analysis.md` (defect F10) for full root-cause, file:line and
suggested approach.

## Staged progress (2026-06-10, erasure-generics Stages A+B — tags BUG-2026-0069-20260610-1..7)

**Stage A — for-each element-type back-propagation (DONE)**: `ForEachDetector.convertForEachPatterns`
now back-propagates the element type revealed by the desugared loop's `(String) it.next()` cast onto
the iterated collection's declaration, via the BUG-2026-0065 `VariableDeclarationStatement.setGenericSignature`
channel (rendered by `SignatureParser.parseFieldSignature` in the writer — no new AST, as planned in
report §3). Conservative: only same-scope `VariableDeclarationStatement`s, only raw single-type-parameter
JDK iterables (whitelist `SINGLE_PARAM_ITERABLES`), only non-Object reference element types, existing
signatures never overwritten. `List var1 = Arrays.asList(...)` + `for (String var4 : var1)` now renders
`List<String> var1`. **C_VarInference FAIL(1)→0.**

**Stage B — known-generic-factory table (DONE)**: `ClassFileToJavaSyntaxConverter.storeLocal` declaration
branch synthesizes the parameterized signature when the initializer is a call to
`Arrays.asList` / `List.of` / `Set.of` / `Map.of` (K,V from alternating args) / `Collections.singletonList` /
`Optional.of` / `Optional.ofNullable` / `Stream.of` and the argument static types are homogeneous
(same erased reference type) or a single `new E[]{...}` varargs reference array (component type used).
Heterogeneous/unknown/Object-typed args and zero-arg factories (`Collections.emptyList`,
`Optional.empty`, `List.of()` — no element type derivable from arguments) stay erased — conservative.
Only fires when the declared type IS the factory container (the no-LVTT case) and no LVTT signature
exists. **C_Optional FAIL(1)→0; C_StreamsAdvanced FAIL(3)→0** (all three errors were factory-typed
locals feeding stream chains — no Stage-C dependency there after all).

**Sub-symptom (b) follow-up**: array loads (`iaload..saload`) carried a hardcoded `int` element type;
`aaload`/`baload` now derive the component type from the array expression's static type (other opcodes
typed per opcode). This fixes the array-foreach element garble for reference arrays without LVT
(`for (int v : String[])` → `for (String v : ...)`) and `int x = args[0]`-style declarations.

**Sub-symptom (a) partial**: the incompatible-type half of reused-slot damage is fixed by the
BUG-2026-0096 category-conflict slot split. RESIDUAL: a result variable first assigned inside an
if-branch is still declared there instead of before the `if` (T7SlotReuse.reuse: `String var2`
declared in then-branch, referenced in else/return → 2 errors; baseline was 6) — flow-level
declaration hoisting, NOT covered by the BUG-2026-0077 promotion pass.

**Stage C (indy instantiatedMethodType → functional-interface locals) NOT in this batch** — hard
requirement for C_FunctionalInterfaces(9)/C_VarLambdaParams(5, was 8). Matrix after A+B: 52/57 clean.
