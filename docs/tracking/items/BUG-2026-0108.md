# BUG-2026-0108: typeSwitch labels stored as CONSTANT_Dynamic render as 'case  _'

**Type**: Bug
**Status**: TO_ANALYZE
**Severity**: HIGH
**Created**: 2026-09-05

## Description
Pattern-switch labels that javac stores as a CONSTANT_Dynamic pool entry are not decoded, so the arm prints `case  _`. Affects qualified enum constants (`case DayOfWeek.MONDAY`, a Java 21 GA feature) and the JEP 507 primitive-pattern previews (`case true`/`case false` via getStaticFinal, primitiveClass labels).

## Technical Analysis
The indy bootstrap-argument reader accepts only CONSTANT_Class / String / Integer; any other tag falls through to `getUtf8`, which returns null for tag 17, and the arm builders then synthesise `_` for the unparsable label.

### Suggested Approach
Add a condy label resolver: `ConstantBootstraps.invoke` + `EnumDesc.of` -> `Enum.CONSTANT` (plus import); `getStaticFinal` Boolean.TRUE/FALSE -> `true`/`false`; `primitiveClass` -> primitive type pattern; tags 5/4/6 -> long/float/double literals. Keep the existing label-list format.
