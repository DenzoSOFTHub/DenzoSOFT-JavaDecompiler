# BUG-2026-0117: ldc/ldc_w of CONSTANT_Dynamic emits the literal string "/* constant:N */"

**Type**: Bug
**Status**: IN_ANALYSIS
**Severity**: MEDIUM (silent wrong value)
**Created**: 2026-09-05
**Source**: `docs/reports/report-java25-plus-audit.md` §BUG-2026-0117 (audit of 2026-09-05, v1.10.0
baseline).

## Description
An `ldc` / `ldc_w` whose constant-pool entry is `CONSTANT_Dynamic` falls into a default branch that
returns a STRING CONSTANT whose text is `/* constant:N */`. The output compiles and reads like a
comment, but it is a string literal standing where a value of some other type belongs — a silent wrong
value, which is this project's most serious defect class.

Forward-looking: javac emits no condy in `ldc` position today (0 occurrences in JDK 25 `java.base`),
but other compilers and bytecode generators do.

## Technical Analysis
The default branch of the constant decode builds a `StringConstantExpression` for any pool tag it does
not recognise, instead of declining.

**Re-verified 2026-09-07**: still present, now at
`ClassFileToJavaSyntaxConverter.java:4947`:
```java
default: return new StringConstantExpression(line, "/* constant:" + index + " */");
```
(The audit cited :4437-4447 at v1.10.0.)

### Suggested Approach
Build a pseudo static call on the bootstrap owner/name with the rendered static arguments, and record
a `CONDY_UNSUPPORTED` diagnostic. **Never emit a string literal for a non-string constant** — per
CLAUDE.md, a recorded diagnostic beats a plausible-looking wrong value.
