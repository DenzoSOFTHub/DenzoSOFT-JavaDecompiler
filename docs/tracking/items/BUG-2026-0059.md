# BUG-2026-0059: Record implicit members emitted verbatim (invalid canonical ctor + broken auto methods)

**Type**: Bug
**Status**: RESOLVED
**Severity**: CRITICAL
**Created**: 2026-06-08
**Resolved**: 2026-06-08

## Description
Every `record` leaks its compiler-generated members: an explicit canonical constructor (javac: "invalid
canonical constructor in record X"), redundant trivial accessors, and `toString`/`hashCode`/`equals`
rendered as `return arg0 -> { };`. Result: 24 recompile errors on a 4-record file.

## Technical Analysis
`JavaSourceWriter` suppresses synthetic members only for `isEnum()` (top-level loop ~549-557, inner loop
~856-863); there is no `isRecord()` branch even though `getRecordComponents()` is captured. Combined with
BUG-2026-0058 (ObjectMethods decoded as a null-body lambda), the implicit members render as garbage.

### Suggested Approach
Add record-member suppression to both method loops: skip the auto `toString`/`hashCode`/`equals` (body is
the ObjectMethods sentinel from BUG-2026-0058), skip trivial component accessors (`return this.<comp>;`),
and suppress the trivial canonical constructor; when the canonical constructor carries extra statements
(a user compact constructor with validation), emit it in **compact** form (`Name { <validation> }`).

### Affected Modules
- `service/writer/JavaSourceWriter.java`

### Estimated Effort
MEDIUM

See `docs/reports/report-decompilation-defect-analysis.md` (defect F01).

## Solution Implemented
Added `isImplicitRecordMember(method, componentNames)` to `JavaSourceWriter`, called from both the
top-level and nested method-emission loops (guarded by `result.isRecord()` / `inner.isRecord()`). It
suppresses:
- auto `toString`/`hashCode`/`equals` — detected by the ObjectMethods sentinel in the body (BUG-2026-0058);
- trivial component accessors — `return this.<comp>;` (a leading erasure cast `(A) this.first` is unwrapped);
- the trivial canonical constructor — body consisting only of `super()` / `this.<comp> = ...` / empty return.

A canonical constructor that carries extra logic (a user compact constructor with validation) is **never**
suppressed, so no user code is silently lost.

### Files Modified
- `service/writer/JavaSourceWriter.java` - record-member suppression hooks + `isImplicitRecordMember`/`bodyReturnsObjectMethods`/`bodyIsTrivialAccessor`/`canonicalCtorIsTrivial` helpers

### Result
J16Records recompile errors 24 → 1; J17Sealed 10 → 6 (records clean; residual is F06/F05). `record Point(int x, int y) {}` now reconstructs exactly.

### Test Case
- Test class: `DecompilerTest`
- Test method: `testRecordImplicitMembers` (a record decompiles to `record RecPoint(int x, int y) {}` with no `-> {`, no `ObjectMethods`, no synthetic ctor)
- Verifies: implicit record members are suppressed; genuine user members (compact ctor, overridden accessor) are kept.

### Known remaining edge
A validating canonical constructor still renders in explicit (non-compact) form with `super()` and
`arg0`-named parameters → javac "invalid canonical constructor" (1 residual error on `Range`). Emitting it
as a compact constructor requires renaming parameters to component names (an AST rebuild); tracked as a
follow-up. Common records (no validation) are fully correct.
