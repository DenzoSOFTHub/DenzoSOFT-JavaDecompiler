# BUG-2026-0086: Conditional branching to current loop exit (continue-outer) silently discards loop body

**Type**: Bug
**Status**: RESOLVED
**Severity**: HIGH
**Created**: 2026-06-10
**Resolved**: 2026-06-10
**Cluster**: `loop-exit-branch` (construct-matrix gap analysis, fix order #6)
**Parent/related**: NEW (hardening also helps BUG-2026-0056 catch-body drop) — umbrella BUG-2026-0080

## Description

Class of defect: decompile→recompile failure. Matrix classes affected: C_ControlFlow.

- **C_ControlFlow**: Compiles but wrong output: labeledContinue's inner loop body is completely lost. Decompiled: 'for (int var3 = 0; var3 < arg0; var3++) { int var4 = 0; while (var4 < arg0) { } }' — an empty infinite inner while; the original 'if (j > i) continue loop;', 'count++' and 'j++' all vanish, and the 'loop:' label is gone. (Contrast: labeledBreak in the same class decompiles correctly via the existing labeled-break path.)

## Technical Analysis

### C_ControlFlow (confidence: HIGH)

A conditional whose taken branch is a goto to the current loop's exit (continue-outer / break-inner shape) matches NO pattern and is silently discarded. CFG: inner while header B12 (exit 36), body conditional B18 = 'if_icmple 27' with fall-through B24 = 'goto 36' (36 = outer increment = inner exit), B27 = 'count++; j++; goto 12'. Trace: Pattern 1 matches the inner while (StructuredFlowBuilder.java:688) and pushes loopExitPc 36 onto outerLoopMergePoints (692), then builds the body from B18 with stopPc=12. In matchConditionalPattern(B18): Pattern 2's computeMergePointImpl (914-930) returns 36 (endOfTrue=B24 goto), but the BUG-2026-0014 guard (774-785) voids it because mergePoint(36) > stopPc(12) AND 36 >= outerLoopMergePoints entry 36 — the inner loop's OWN exit — setting mergePoint=-1. Pattern 3 (836) fails: isTerminalBlock(B24) walks 24->36->(goto back to header 4 -> conditional) and returns false (1454-1467). matchConditionalPattern returns null (849). Back in buildFromBlock0, the unmatched CONDITIONAL block emits its (empty) statements (429) and hits the final 'else return' (472-473), dropping BOTH successors — B27 with count++/j++ is never visited. The existing labeled-break machinery (447-467) is never reached because the builder never descends into B24.

### Suggested Approach

In StructuredFlowBuilder.matchConditionalPattern's BUG-2026-0014 guard (:774-785): when mergeExceedsOuterExit AND the true/false target is a goto to an outerLoopMergePoints entry, set mergePoint to the other branch's startPc instead of voiding — the existing goto handling (:448-462) then emits a labeled break wrapped by the :757 label, recovering 'continue outer' as 'break label'. Additionally harden buildFromBlock0:470-473 so an unmatched CONDITIONAL never silently drops both successors (fall back to recursively building an if with both branches) — prevents whole-body loss for future unmatched shapes and the BUG-2026-0056 catch-conditional drop.

Per-finding fix details:

- In matchConditionalPattern's BUG-2026-0014 guard (StructuredFlowBuilder.java:774-785): when mergeExceedsOuterExit AND the trueTarget (or symmetrically falseTarget) is a goto block whose branchTargetPc equals one of the outerLoopMergePoints entries, do NOT void the merge — set mergePoint to the other branch's startPc (falseTarget.startPc, here 27) and let the existing if-then path (819-831) run. buildFromBlock(trueTarget=B24, ..., stopPc=27) then hits the existing goto handling: target 36 > stopPc 27 triggers line 448, matches outerLoopMergePoints entry 36 (451-462), emits a labeled break and registers the label that line 757 wraps around the inner while — yielding 'label: while (j < n) { if (j > i) break label; count++; j++; }', semantically equivalent to the original continue-outer. Optional refinement: when the matched exit is the INNERMOST entry (oli == size-1), emit a plain unlabeled break instead. Additionally, harden buildFromBlock0:470-473 so an unmatched conditional does not silently return (e.g. fall back to emitting an if with both branches recursively built), preventing whole-body loss for future unmatched shapes.

## Solution Implemented

In `StructuredFlowBuilder` (tags `BUG-2026-0086-20260610-1..9`):

1. **Merge redirection in the BUG-2026-0014 guard** (tag -1): when the merge exceeds an outer
   loop exit AND the true (or false) branch is a goto whose target equals an
   `outerLoopMergePoints` entry, the merge is REDIRECTED to the other branch's start PC instead
   of being voided. The if-then path then builds the goto branch as the then-body; the existing
   goto handling emits the labeled break and registers the label that Pattern 1 wraps around the
   loop. C_ControlFlow.labeledContinue now decompiles as
   `outer: for (j...) { if (j > i) break outer; count++; }` — semantically identical to the
   original `continue loop;` (previously the entire inner body vanished, leaving a compiling
   infinite loop).
2. **Unmatched-conditional hardening** (tag -2): `buildFromBlock0`'s terminal else no longer
   silently drops both successors of a CONDITIONAL block that matched no pattern; it now emits a
   structural if/else with both forward, unvisited successors recursively built and bounded by the
   current stopPc (if one side is empty, a plain `if` with the condition oriented accordingly).
3. **Continue-target tracking** (tags -3..-8, found via the switch-in-loop regression test):
   `loopContinueTargets` stack records each loop's continue target — the start of the LAST block
   jumping back to the header (for-loop increment block) for Pattern-1 loops, the condition block
   for do-while, and a -1 sentinel for while(true). A forward goto to the innermost entry (when it
   is not the natural region end) is emitted as `ContinueStatement`. Previously such gotos hit the
   generic goto-beyond-stopPc path and became plain `break` — `continue` inside a switch inside a
   loop silently exited the loop.
4. **Switch traversal in the back-edge walk** (tag -9): `hasDirectBackEdge` now follows a SWITCH
   block's forward case/default targets, so a loop whose body starts with a switch is recognized
   by Pattern 1 (previously the walk stopped dead, the loop degenerated to a bodyless
   `while (true)` and the entire body was lost).
