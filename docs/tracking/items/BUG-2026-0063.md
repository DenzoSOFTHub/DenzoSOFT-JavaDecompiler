# BUG-2026-0063: Array local declaration loses its `[]` (element type used as declared type)

**Type**: Bug
**Status**: RESOLVED
**Severity**: HIGH
**Created**: 2026-06-08
**Resolved**: 2026-06-08

## Description
`int[] a = {1,2,3}` decompiled to `int a = new int[]{1,2,3}` → "int[] cannot be converted to int", because
`NewArrayExpression` carries the ELEMENT type and RHS type-inference copied it into the declaration.

## Solution Implemented
`storeLocal` now wraps the inferred type in `ArrayType(elementType, dims)` when the initializer is a
`NewArrayExpression` (dims taken from the dimension-expression count, folding a nested element ArrayType).

### Files Modified
- `service/converter/ClassFileToJavaSyntaxConverter.java`

### Known remaining
Multi-dimensional initializers (`int[][] m = {{..},{..}}`) still need the nested aastore collector
(defect F10); single-dimension arrays are fixed.
### Status: CLOSED (pending release move)

## Update — nested array initializer rendering (session 6)
The writer rendered nested (multi-dimensional) array initializers as a `[]{/* N elements */}` placeholder;
it now renders the real element values recursively (`new int[]{new int[]{1, 2}, new int[]{3, 4}}`). The outer
array's declared dimension in the multianewarray decode remains a separate decoder gap.
### Files Modified
- `service/writer/JavaSourceWriter.java` (writeExpressionSimple NewArrayExpression branch)
