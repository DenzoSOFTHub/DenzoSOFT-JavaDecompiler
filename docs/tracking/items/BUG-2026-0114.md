# BUG-2026-0114: altMetafactory lambdas rendered as chained casts

**Type**: Bug
**Status**: IN_ANALYSIS
**Severity**: MEDIUM
**Created**: 2026-09-05
**Source**: `docs/reports/report-java25-plus-audit.md` §BUG-2026-0114 (audit of 2026-09-05, v1.10.0
baseline).

## Description
Serializable and intersection-type lambdas, which javac routes through
`LambdaMetafactory.altMetafactory`, are emitted as chained casts:
`(Runnable) (Serializable) () -> { return; }`. This does not compile — `Serializable` is not a
functional interface. The correct rendering is a single intersection cast, `(Runnable & Serializable)`.

Evidence: `probe/dec/P_Generics.java:181` (audit workspace); in JDK 25 `java.base`,
`ChronoLocalDate.java:260`, `ChronoZonedDateTime.java:141`, `TreeMap.java:3383`
(`(Comparator) (Serializable) (a, b) -> ...`). 8 classes in `java.base` use `altMetafactory`.

## Technical Analysis
The converter treats `altMetafactory` exactly like `metafactory`; the flags and marker interfaces
carried in `bootstrapArguments[3..]` are ignored. (Audit cites `Converter.java:3150-3260`.)

**Re-verified 2026-09-07, and the finding is stronger than the audit stated**: the string
`altMetafactory` does not appear ANYWHERE in `src/main/`, and neither does any `FLAG_SERIALIZABLE` /
`FLAG_MARKERS` handling. The bootstrap is not distinguished from `metafactory` at all.

### Suggested Approach
Parse the extra bootstrap arguments: `FLAG_SERIALIZABLE = 1`, `FLAG_MARKERS = 2`, `FLAG_BRIDGES = 4`;
collect the marker interfaces that follow; emit one intersection cast `(Iface & Marker) lambda`.

### Affected Modules
- `src/main/java/it/denzosoft/javadecompiler/service/converter/ClassFileToJavaSyntaxConverter.java`
