# BUG-2026-0204: GUI "Compact Output" option has no effect

**Type**: Bug
**Status**: TO_ANALYZE
**Severity**: LOW
**Created**: 2026-10-30

## Description

*Options > Compact Output* in the GUI can be ticked, but the decompiled source looks the same either
way. The GUI always shows the dense layout; the line-aligned layout (the CLI default, which keeps
statements on their original source line numbers) is not available in the GUI at all.

## Technical Analysis

- `DecompilerGui.optCompact` is set by the menu item and exposed by `isCompactMode()`, but nothing
  reads it.
- `JarPanel.decompileClass()` passes only `getDecompilerConfig()` (bytecode, native info,
  deobfuscate) to the decompiler.
- Line alignment is a printer concern: `JarPanel.StringPrinter.startLine(int)` ignores the line number,
  so even with the option wired through, the GUI printer would not align.

### Suggested Approach

Either implement alignment in the GUI printer (reuse the CLI printer's logic from `Main`) and select it
from `isCompactMode()`, or remove the menu item. Aligned output is useful in the GUI for matching stack
traces, so the first is preferable.

### Affected Modules

`gui/DecompilerGui.java`, `gui/JarPanel.java`, possibly `Main.java` (printer reuse)

### Estimated Effort

LOW
